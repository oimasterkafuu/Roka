# 简单策略 Bot 模板

这个目录提供了一个具备综合策略评估能力的 Roka 机器人，可以完整打完一局对局。

与 `random-patch-bot`（每回合随机走子的最小参考实现）不同，本 bot 每个 tick 运行一条
「威胁推演 → 防御 → 进攻 → 经济 → 后勤」的综合评估管线（`strategy.js` 编排，`bot/` 下各
纯函数模块分工）：

- **威胁推演与防御计算**（`bot/defense.js`）：对每个成规模的敌军 blob 用 Dijkstra 推演其
  进攻我方锚点（主城/指挥所）代价最低的路径，并按战斗规则逐格模拟兵力损耗，提前算出
  「多少 tick 后、带多少兵打到哪里」；据此贴脸歼灭/削弱、直接反击兵源，或在威胁路径上
  选集结点提前布防；主城守不住时多主城提前撤空、单主城全军出击；
- **集结打击与切断入侵**（`bot/offense.js`）：评估敌方主城/指挥所目标（端掉最后一座主城
  = 直接淘汰），用带「邻近敌军风险」代价的最短路选择更难被破解的进军路径；入口兵力不足
  时以入口为焦点多源集结（穿过己方格自动合流，而非只从单一大点取兵），兵力够了再全冲
  推进；深入我境的敌军一旦可吃立即切断；
- **铺皇冠经济**（`bot/economy.js`）：皇冠每 tick +1 产兵、是普通格的 50 倍，
  因此**不设数量上限**——普通格兵力过门槛就按「**皇冠簇优先**（贴着现有锚点
  大幅加分、远离锚点的飞地扣分）+ 二线甜区」评分建指挥所；**升级优先于新建**：
  指挥所兵力一回血（≥52）立即升皇冠（不设冷却、评分显著高于新建），让产能复利
  滚动；开局尽早补第二锚点（生存保险），威胁逼近时自动冻结建设把兵力留给防御，
  差十几兵就能建的内陆格与簇内格（贴锚点、2 兵起喂）由输送流顺路喂养过门槛；
- **汇集输送与扩张**（`bot/logistics.js`）：向集结焦点（防御 rally / 打击入口 /
  喂养目标）做多链路 BFS 距离场输送；无焦点时沿前线距离场运兵；中立/孤军领土用
  智能分兵（`mode=0`，自动为其他方向敌军保留防御兵力）扩张，爆发期加权；
- **稳定执行**：推兵量用与引擎 `computePush` 一致的预演（推不动就不下发，不白耗执行
  名额）；与队列镜像相同的 op 不重复入队；集结点跨 tick 滞后保持防往返；每 tick 最多
  2 条操作、本地队列不超过 3 条，紧急防御抢占队列。

对局结束（`game_end`）后连接不断开，留在房间内等下一局自动准备；断线重连后会自动重新进房（对局进行中则走服务端 10 秒宽限期换绑恢复）。

本目录的 `strategy.js` 同时被服务端内嵌运行复用（超级管理员在后台管理页 `/admin` 启动的策略
Bot 直接加载本文件，见 `src/server/server-bot-manager.ts`），修改策略对两种运行方式同时生效。

## 1）手动获取鉴权 token

登录流程包含验证码，因此机器人无法完全自动登录。

1. 先在浏览器中登录账号。
2. 打开开发者工具，进入 Application/Storage -> Cookies。
3. 复制名为 `auth_token` 的 Cookie 值。

## 2）安装与运行

```bash
cd bot-template/simple-strategy-bot
pnpm install
BOT_SERVER=http://127.0.0.1:23333 BOT_ROOM=your-room BOT_TOKEN=your-auth-token pnpm start
```

可选环境变量：

- `BOT_TEAM`（默认值：`1`，组队模式下的目标队伍号）
- `BOT_AUTO_READY`（默认值：`1`，设为 `0` 关闭自动参赛与准备）
- `BOT_ACTION_DELAY_MS`（默认值：`120`，每回合决策后的发送延迟）

## 3）由管理员在服务端启动（无需 token）

超级管理员也可以在后台管理页 `/admin` 的「策略 Bot」分区直接启动本
bot：只需提供已注册的用户名与房间号，服务端会在本进程内完成登录（跳过验证码）并运行同一套策略；
Bot 进房不会成为房主（房主保留给后续进房的人类用户或第三方 bot），对局结束后自动重新准备，
也可在管理页手动停止。
