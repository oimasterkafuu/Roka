# 简单策略 Bot 模板

这个目录提供了一个具备综合策略评估能力的 Roka 机器人，可以完整打完一局对局。

与 `random-patch-bot`（每回合随机走子的最小参考实现）不同，本 bot 每个 tick 运行一条
「威胁推演 → 防御 → 切断救援 → 进攻 → 开局规划 → 经济 → 后勤」的综合评估管线（`strategy.js` 编排，
`bot/` 下各纯函数模块分工）：

- **开局发育规划**（`bot/opening.js`）：约 1–50 tick 且无活敌逼近时接管——逐 tick 对
  「憋 w 拍再开工」的蛇形推进方案做整场模拟（真实增长规则 + 贪心推进/补链），按
  「爆发期产兵总量 + 地皮」评分选最优启动时机（最优解往往不是第 1 tick 就动，而是先空
  几回合）；爆发期（26–50 tick）优先扩张新地而不是立刻建造；敌情出现即交还常规管线；
- **威胁推演与防御计算**（`bot/defense.js`）：对每个成规模的敌军 blob 用 Dijkstra 推演其
  进攻我方锚点（主城/指挥所）代价最低的路径，并按战斗规则逐格模拟兵力损耗，提前算出
  「多少 tick 后、带多少兵打到哪里」。威胁分两层：**只有正在逼近（hops 缩小）的威胁**
  才触发集结布防、冻结经济与暂缓新进攻；静止的龟缩兵堆只做贴脸应急与「可吃即切」，
  不为它拖垮自己的皇冠生产线。防御闩锁保证「守得住 ↔ 守不住」平衡点上集结焦点不
  高频抖动；集结点带滞后保持、路径上已有守得住的格时不再集结，防止输送流往返倒兵；
  主城守不住时多主城提前撤空、单主城全军出击；
- **切断救援**（`bot/rescue.js`）：某片领土被敌方截断（与锚点失联、孤军化）时，推演
  最便宜的重连走廊（孤军格不能移动，救援只能从连通侧打出去；打通一格即整片重连，
  且重连时兵力翻倍）——可交付兵力足够就组织救援打击，入口不足先以入口为焦点集结；
  明显救不了的区域止损不投入，避免继续白送；
- **集结打击、前线突破与切断入侵**（`bot/offense.js`）：评估敌方主城/指挥所目标（端掉
  最后一座主城 = 直接淘汰）与高价值敌方咽喉切断点（切断即让其后方无锚区域孤军化），
  用带「邻近敌军风险」代价的最短路选择更难被破解的进军
  路径；入口兵力不足时以入口为焦点多源集结（穿过己方格自动合流），推兵量到需求 85%
  即开打（碾压优势时门槛降到 50%，不拖烂尾局）。行军纪律：**锚点起步一律半兵**
  （主力出征家里留半，根治倾巢换家）、**活跃威胁逼近即全军回防**（除非斩首比对方
  破城更快）、**新打击需求不得超过机动兵力**（全军 − 各格驻军保留）；没有打击计划时
  转入**前线突破集结**——挑一个集结后可突破的对峙点做输送焦点，让前线兵力朝同一
  方向汇集成股而不是零散停滞；**对峙记忆**——活跃威胁（含闩锁/宽限平滑）消停满
  12 tick 才开新打击，不在平衡点上反复立/废计划；进行中打击逐拍体检——目标被
  大幅增援即弃打止损（集结期皇冠 +1/tick 的自然增长不算增援）、集结缺口连续扩大
  （产能跟不上）即弃打转发育（可交付已饱和时不追踪），弃打目标进入冷却防止反复
  立计划空耗输送；深入我境的活敌格一旦可吃立即切断（腹地越深处优先级
  越高，压过常规打击与集结输送）；
- **铺皇冠经济**（`bot/economy.js`）：皇冠每 tick +1 产兵，而**指挥所与普通格一样每
  50 tick 才 +1（不增产）**，因此指挥所只是通往皇冠的中间态——普通格攒到 **101 兵**
  （建城剩 51、下回合即过升级线直接升冠，**b/c 连续两回合完成**）才按「**皇冠簇优先**
  + 二线甜区 + 咽喉格加分」评分建指挥所；**升级优先于新建**：指挥所兵力一过升级线
  立即升皇冠；开局尽早补第二锚点（连通保险），威胁逼近时自动冻结建设把兵力留给防御；
- **驻军保留线**（`bot/board.js` 的 `garrisonAt`，贯穿所有模块）：边境格保留邻敌
  推兵量；**咽喉格**（在己方领土割点分析中，切断它会让 ≥3 格无锚区域整片失联的格子）
  按双层危险场定量留守——扑击层（所有活敌、限 3 步，贴身敌格再不动也能一两拍扑到）
  与压境层（仅正在逼近的敌人、限 14 步）取逐格最大，远处龟缩不动的兵堆不冻结走廊；
  进攻、输送、集结都不得把要道抽空，只有紧急防御集结可破格；
- **汇集输送与扩张**（`bot/logistics.js`）：向集结焦点（防御 rally / 救援走廊 / 打击
  入口 / 突破点 / 喂养目标）做多链路 BFS 距离场输送；评分分两档——**常规集结大栈
  优先**（推兵加分封顶 600、距离轻扣：一支肥纵队每 tick 推进一格全速送达，弃打遗留
  在死角的大兵堆也会被抽回主干网），**紧急集结/无焦点增援就近优先**（少量快送续命）；
  无焦点时只向贴着活敌的暴露前线格补线，没有暴露前线就赋闲（兵留在皇冠上自然增长，
  不往前线平摊停滞）；**常规输送每 tick 限 1 条 op**（紧急集结除外），防止集结/输送
  长期挤占扩张与建设；中立/孤军领土用智能分兵（`mode=0`）扩张；**12–25 tick 抢地冲刺**
  与爆发期（26–50 tick）普通格扩张加权，空地永远优先于沼泽；升级链保护：未稳过升级线的
  指挥所不作输送/扩张源；源格推兵后跌破驻军保留线时自动降半兵、再不行才不动；
- **稳定执行**：推兵量用与引擎 `computePush` 一致的预演（推不动就不下发，不白耗执行
  名额）；与队列镜像相同的 op 不重复入队；`recentMoves` 记录最近数 tick 的移动方向，
  恰好互逆的非紧急移动直接丢弃（防往返抖动）；集结点与救援走廊跨 tick 承诺保持；
  每 tick 最多 2 条操作、本地队列不超过 2 条，紧急防御抢占队列；打击行军时把下一步
  也预排进队列加速推进。

对局结束（`game_end`）后连接不断开，留在房间内等下一局自动准备；断线重连后会自动重新进房（对局进行中则走服务端 10 秒宽限期换绑恢复）。

本目录的 `strategy.js` 同时被服务端内嵌运行复用（超级管理员在后台管理页 `/admin` 启动的策略
Bot 直接加载本文件，见 `src/server/server-bot-manager.ts`），修改策略对两种运行方式同时生效。

## 1）手动获取鉴权 token

登录流程包含验证码，因此机器人无法完全自动登录。

1. 先在浏览器中登录账号。
2. 打开开发者工具，进入 Application/Storage -> Cookies。
3. 复制名为 `auth_token` 的 Cookie 值。

## 2）安装与运行

```bash
cd bot-template/simple-strategy-bot
pnpm install
BOT_SERVER=http://127.0.0.1:23333 BOT_ROOM=your-room BOT_TOKEN=your-auth-token pnpm start
```

可选环境变量：

- `BOT_TEAM`（默认值：`1`，组队模式下的目标队伍号）
- `BOT_AUTO_READY`（默认值：`1`，设为 `0` 关闭自动参赛与准备）
- `BOT_ACTION_DELAY_MS`（默认值：`120`，每回合决策后的发送延迟）
- `BOT_TRACE`（默认关闭；`1` 打印进攻评估/焦点/闸口决策，`2` 再加每 tick 候选榜，
  离线复盘与调参用；配合 `scripts/replay-bot-decisions.mjs` 可逐 turn 复盘录制对局）

## 3）由管理员在服务端启动（无需 token）

超级管理员也可以在后台管理页 `/admin` 的「策略 Bot」分区直接启动本
bot：只需提供已注册的用户名与房间号，服务端会在本进程内完成登录（跳过验证码）并运行同一套策略；
Bot 进房不会成为房主（房主保留给后续进房的人类用户或第三方 bot），对局结束后自动重新准备，
也可在管理页手动停止。
