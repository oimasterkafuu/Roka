# 简单策略 Bot 模板

这个目录提供了一个具备中等强度策略的 Roka 机器人，可以完整打完一局对局。

与 `random-patch-bot`（每回合随机走子的最小参考实现）不同，本 bot 的决策有明确的战略考量：

- **主城防卫**：敌军与我方主城相邻时，优先从相邻最强兵力格全冲（`mode=2`）反击——能歼灭（攻击兵力严格大于守军）就歼灭，军情紧急时先削弱；
- **扩张占地**：边界格用智能分兵（`mode=0`，自动为其他方向敌军保留防御兵力）占领中立格，优先 0 兵空地，中立沼泽优先级最低；
- **歼敌推进**：兵力严格占优（己方兵力 − 1 > 守军）时全冲攻击敌军，敌方主城优先级最高；
- **腹地运兵**：不临前线的腹地格兵力沿 BFS 距离场（到最近非己方格）逐格向前线输送；
- **择机建设**：腹地高兵力普通格建指挥所（`build b`，耗 50 兵），指挥所兵力充足再升级主城（`build c`）获得每 Tick +1 生产；建设有回合间隔限制，避免拖垮前线；
- **队列控制**：用 `update.lst_move` 同步本地队列镜像，每回合最多下发 2 条操作、本地队列不超过 3 条，避免过期指令堆积。

对局结束（`game_end`）后连接不断开，留在房间内等下一局自动准备；断线重连后会自动重新进房（对局进行中则走服务端 10 秒宽限期换绑恢复）。

本目录的 `strategy.js` 同时被服务端内嵌运行复用（超级管理员在后台管理页 `/admin` 启动的策略
Bot 直接加载本文件，见 `src/server/server-bot-manager.ts`），修改策略对两种运行方式同时生效。

## 1）手动获取鉴权 token

登录流程包含验证码，因此机器人无法完全自动登录。

1. 先在浏览器中登录账号。
2. 打开开发者工具，进入 Application/Storage -> Cookies。
3. 复制名为 `auth_token` 的 Cookie 值。

## 2）安装与运行

```bash
cd bot-template/simple-strategy-bot
pnpm install
BOT_SERVER=http://127.0.0.1:23333 BOT_ROOM=your-room BOT_TOKEN=your-auth-token pnpm start
```

可选环境变量：

- `BOT_TEAM`（默认值：`1`，组队模式下的目标队伍号）
- `BOT_AUTO_READY`（默认值：`1`，设为 `0` 关闭自动参赛与准备）
- `BOT_ACTION_DELAY_MS`（默认值：`120`，每回合决策后的发送延迟）

## 3）由管理员在服务端启动（无需 token）

超级管理员也可以在后台管理页 `/admin` 的「策略 Bot」分区直接启动本
bot：只需提供已注册的用户名与房间号，服务端会在本进程内完成登录（跳过验证码）并运行同一套策略；
Bot 进房不会成为房主（房主保留给后续进房的人类用户或第三方 bot），对局结束后自动重新准备，
也可在管理页手动停止。
