# Relay 对局评测

两个调参结束后启用的固定种子，每个种子在随机、迷宫、群岛和地中海四种地形上交换出生位。四个对手均通过托管入口 `attachStrategy` 参赛。使用正式引擎的 1v1 尺寸、增长、调度和战斗规则，每个策略只收自己座位的开局与更新帧。测试时钟每 Tick 推进 500 毫秒。所有胜负均取自实际终局，达到 1000 Tick 仍有两名存活者记为超时。

每个对手各 128 局。按胜 / 负 / 超时统计，Simple 为 107 / 3 / 18，Anti-Human 为 75 / 23 / 30，Apex 为 92 / 19 / 17，Bot 2.0 为 88 / 18 / 22。

在打到第 50 Tick 的 510 局中，第 25 Tick Relay 平均占地 19.1 格，对手为 17.1 格。第 50 Tick 的平均兵力分别为 1006 和 644。多线中这些开局优势往往能转化为胜局。大图迷雾单线的收尾仍弱，64 局中有 52 局到达上限。另以首个验证种子在随机大图、迷雾单线下复跑 8 局，将上限延长到 2400 Tick。与 Simple、Anti-Human 交手的 4 局仍然超时，与 Apex、Bot 2.0 交手的 4 局均在 915 Tick 内获胜。延长局独立于上表。

## 复现

在仓库根目录使用 Node.js 22 或更高版本和项目指定的 pnpm。评测采用 Node 的模拟时钟；地图可由种子复现，对手的决策耗时和运行时随机性可能影响逐局结果。

```sh
pnpm install --frozen-lockfile
pnpm run build
SEEDS=relay-validation-1,relay-validation-2 TICKS=1000 node scripts/evaluate-relay.cjs > /tmp/relay-validation.jsonl
```

`OPPONENTS` 可选 `simple,anti,apex,v2`，`MAPS` 指定地形，`MODES` 以三位数字依次表示大图、迷雾、多线。例如 `MODES=110 MAPS=random` 表示随机大图、迷雾、单线。评测通过标准输出返回 JSONL，`seat` 为 Relay 的零基座位号，`executed` 按座位列出引擎成功执行的指令数，`checkpoints` 按座位记录各时点的 `[领土, 兵力]`。本轮完整原始数据见 [results.jsonl](results.jsonl)。
