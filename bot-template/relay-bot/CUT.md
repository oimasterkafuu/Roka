# 切断经济学层（cut）

`cut.js` 是隔离/切断方向的实验层：它只改评分（以及 `BOT3_ARTIC` 额外提出建造候选），不保存任何状态、不读时钟、不用随机数。全部开关默认关闭，关闭时逐局结果与基线 `baseline-results.jsonl` 完全一致（4 种子屏幕逐行 `diff` 为空）。

## 引擎事实（诊断依据）

- `applyConnectivity` 每 Tick 在所有己方**锚点**（主城 -2 / 指挥所 -1）上做一次多源 BFS：连到任一锚点的格子为正常，其余格子被标记 `isolated`。新断链的格子**立即减半**（1 兵例外），随后 10 Tick 宽限，之后每回合（2 Tick）衰减 5%，减到 0 变中立；重新连回时**兵力翻倍**（该孤军周期内被推过兵则翻倍失效）。
- `applyTickGrowth` 在**移动阶段之前**执行：主城每 Tick +1；普通格/指挥所在 `turn % 50 === 0` 且非孤军时 +1。
- 出生顺序：`strategy.js` 用 `frame.turn = T` 的状态决策，指令在 **Tick T+1** 执行。因此“在 Tick 49 落下切断”的决策点是 `turn % 50 === 48`（`BOT3_CUTTIME_PHASE`），这样被切断区域从 Tick 50 的 +1 开始就再也拿不到。
- 锚点格子**永远不会被标记孤军**：把它升级成指挥所/主城，等于给它背后的整片区域上保险（BFS 从这里出发）。代价是锚点格可被攻占，攻占即摧毁建筑并带走全部驻军。

## 五个机制

| 开关                                           | 默认 | 机制                                                                                                                                                             |
| ---------------------------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BOT3_CUTTIME`                                 | 关   | 时间：`turn % 50 === 48` 时，给“本 Tick 必胜”的敌方割点攻击加 `min(cap, gain*sqrt(cut))`（默认 300/600）；可选 `BOT3_CUTTIME_APPROACH` 在风落前走入割点距离场    |
| `BOT3_CUTVALUE`                                | 关   | 定价：敌方割点攻击 `+min(600, 4*cut)`，`cut > 40` 时保底 420，要求 `homes >= 2`                                                                                  |
| `BOT3_ARTIC`                                   | 关   | 加固：对己方最高 `cut` 的割点格提出廉价建造（成本 + 3 兵），要求脱战（`enemyDist >= 3`、七步压力、相邻无敌方大堆）                                               |
| `BOT3_MULTICUT`                                | 关   | 多线：多线房间内敌方割点攻击 `+min(600, 4*sqrt(cut))`（`multi.js` 的 `cut` 层的加法版本，不启用 focus/paint 负向项）                                             |
| `BOT3_CUTSAVE`（本轮新增，方向上唯一的正结果） | 关   | 反向切断：己方被切断的“孤岛”若能被某格重新连回，则该格的攻占价 `+min(cap, 3*pocket)`；`BOT3_CUTSAVE_MIN` 是孤岛兵力门槛（默认 30），`_SURE=1` 只算本 Tick 能打下 |

全量矩阵（4 对手 × 2048 局）只对两个候选跑完：

| 候选                                                            | 合计        | 胜率  | Δ          | 备用种子 17–32（配对自建基线）                     |
| --------------------------------------------------------------- | ----------- | ----- | ---------- | -------------------------------------------------- |
| `BOT3_CUTTIME=1 BOT3_CUTTIME_APPROACH=150 BOT3_CUTTIME_MULTI=0` | 1612/372/64 | 78.7% | **-0.4pp** | 未跑                                               |
| `BOT3_CUTSAVE=1`（min 30）                                      | 1632/355/61 | 79.7% | +0.5pp     | 1581/382/85（77.2%）对 1576/386/86（77.0%），+5 胜 |
| `BOT3_CUTSAVE=1`（min 6）                                       | 1633/353/62 | 79.7% | +0.6pp     | 1592/381/75（77.7%）对 77.0%，+16 胜               |

结论：

1. **切断进攻（CUTTIME/CUTVALUE/MULTICUT）在本次引擎上基本不可用**。原因是可打到的敌方割点极少：随机/迷宫/群岛这类开阔地图上，敌方领土很少有真正的割点贴着我们的可攻击格；trace 显示风落窗口内的敌方候选里 `cut` 中位数为 0。
2. **加固（ARTIC）是负向**：花费 50 兵 + 一个指令去换“后方不会被切断”，在单线里就是拿推进节奏换保险；迷雾房更糟（`enemyDist` 只数可见敌人，安全门形同虚设）。
3. **反向切断（CUTSAVE）是唯一可复现的正结果**：+5…+16 胜/2048（0.2–0.8pp），在两个互不相交的种子块上都是正的。但它没有达成每格 65% 的目标，且逐格仍是 ±1 局噪声（含受保护的 `med/F-` 在 min=6 时 -1 局）。
4. **多线 8 格无法用切断经济学推动**：多线房间的孤岛兵力中位数 1、p90 5、最大 24（单线：中位数 21、p90 72、最大 279），有孤军的 Tick 占比 7%（单线 39.7%）。一格的攻占价换不到任何东西，所以四个切断开关在两个多线种子块上全部 0.0pp。

## 建议

- 全部开关保持默认关闭：没有一个配置满足“Relay 每格 >= 65% 且不低于基线”。
- 下一轮若要多线收益，切断经济学不是路径（见上面第 4 条数据）；`NEXT.md` 的“第二主城经济”仍是多线唯一未被证伪的方向。
- 若要试用 CUTSAVE，用 `BOT3_CUTSAVE_MIN=10`（或 `20`，两者在 Relay 上逐格相同）：1–16 种子块 Relay +7 胜且无退化格，`_MIN=30` 只有 +5（丢掉随机全图单线的 +2），`_MIN=6` 总量同向但多丢两个迷雾单线格。

## 第 8 轮：与迷雾迷宫层组合、定价扫描（默认仍关闭）

第 8 轮把本层与 `BOT3_MAZEFOG3` 放在同一张 16 种子 Relay 矩阵上组合。完整 16 格组合网格与全量 2048 局见 [README.md](README.md)「组合实验」；这里只记录本层的组合与修复结果。

### Relay 组合（512 局/配置）

| 配置                             |              Relay 胜 | 逐格变化                                             |
| -------------------------------- | --------------------: | ---------------------------------------------------- |
| 基线                             |                   269 | —                                                    |
| `CUTSAVE=1`（`_MIN=10`）         |             276（+7） | 随机全图单线 +2、随机迷雾单线 +4、迷宫全图单线 +1    |
| `CUTSAVE=1`（`_MIN=20`）         |             276（+7） | 与 `_MIN=10` 逐格相同                                |
| `CUTSAVE=1`（`_MIN=30`）         |             274（+5） | 随机全图单线的 +2 消失                               |
| `CUTSAVE=1`（`_MIN=6`）          |             274（+5） | 多丢群岛迷雾单线 1 局、地中海迷雾单线 1 局           |
| `CUTSAVE=1` + `CUTTIME=1`        |               273–274 | 时间窗继续是负向，`CUTTIME` 在全部 8 行里都少 1–2 胜 |
| `+ BOT3_MAZEFOG3=1`（`_MIN=10`） | **281（+12，54.9%）** | 再叠加迷宫全图单线 +1、迷宫迷雾单线 +5               |

组合全量 2048 局：**1644/341/63（80.3%，+23 胜，+1.1pp）**，但 5 个退化格各 -1 局：`anti/群岛/迷雾单线`、`anti/迷宫/迷雾单线`、`anti/地中海/迷雾单线`、`apex/迷宫/全图单线`、`apex/随机/全图单线`。

### 归因：本层的退化格

单独跑本层（`BOT3_MAZEFOG3=0`）：`anti/群岛/迷雾单线` 21←22、`anti/地中海/迷雾单线` 24←25（这两格是“胜局变超时”）、`apex/迷宫/全图单线` 26←27、`apex/随机/全图单线` 29←30；收益为 Relay 随机 +6、Relay 迷宫 +1、anti 三个全图单线格各 +1。

逐局追踪（`data/scratch` 风格的单局回放，只读排行榜与 `b.isolated`）：

- `apex/随机/全图单线` 种子 8 座位 0（基线 208 Tick 胜 → 候选 231 Tick 负）：第 97 Tick 我方被切成 70 兵孤岛，之后逐 Tick 衰减到 10，本层持续把兵力往重新连回的那一格输（`pocket=70`、`bonus=min(1400, 3*70)`），于是斩杀节奏被打断。这是**真实的切断**，不是开局生成残留。
- `apex/迷宫/全图单线` 种子 2 座位 0（94 Tick 胜 → 201 Tick 负）：整局只有一次触发（第 63 Tick，`193->180`，`pocket=32`、`bonus=96`、该步评分 143.2 -> 239.2）。一步改动就把“最快斩杀局”变成了竞技局。
- Relay 的收益局是同一个机制的镜像：随机迷雾单线种子 1 双边 205->192 / 504->197，随机全图单线种子 9 座位 0 495->288。

### 定价扫描（未能修复）

| 变体                                       | Relay 随机/迷宫 | apex 迷宫、随机全图单线 | anti 群岛/地中海 迷雾单线 |
| ------------------------------------------ | --------------: | ----------------------- | ------------------------- |
| 默认（`MIN=10`，`GAIN=3`，`CAP=1400`）     |              +6 | -1、-1                  | -1、-1                    |
| `CAP=90`（按 relay 的 +90 重新连回价封顶） |              +5 | -1、-1                  | **-2**、0                 |
| `MIN=6 / 20 / 30`                          |           +5~+7 | -1、-1                  | -1、-1                    |

`CAP=90` 说明退化并非“大额奖励抢了收尾指令”：把奖励压到 90 以下后 `apex` 两格仍然 -1，反而把 `anti/群岛/迷雾单线` 从 -1 拉到 -2。`MIN` 只能搬动这些 ±1 局。原因是结构性的：同一张图对四个对手完全一致，能区分 Relay 与 Apex/Anti 的只有对手行为，而 32 局/格的分辨率下任何价格变化都只是重新排列噪声。

### 结论

本层**保持默认关闭**。`CUTSAVE` 仍是两个开关里唯一在两个互不相交种子块上都为正的机制（`_MIN=30` 时 1632/+11 与备用种子 1581/+5），但它无法做到零退化格，而组合的 +23 胜也以 5 个 -1 局为代价。若要按总量取舍，推荐 `BOT3_MAZEFOG3=1 BOT3_CUTSAVE=1 BOT3_CUTSAVE_MIN=10`（Relay 281/512，+23 胜），并明确接受那 5 局。

## 第 11 轮：定位门禁（默认仍关闭，推荐组合已满足严格门禁）

第 8 轮的结论是「CUTSAVE 无法零退化」。第 11 轮把问题从**改价**换成**改触发条件**：奖励形状（`GAIN`/`CAP`/`MIN`）在第 8 轮已经证明只能搬运 ±1 局，但哪些**局面**该付这一回合的钱仍然可以筛。本层新增四个无状态定位门禁（默认全关，关闭时与第 8 轮逐局一致）：

| 开关                       | 默认 | 含义                                                                         |
| -------------------------- | ---- | ---------------------------------------------------------------------------- |
| `BOT3_CUTSAVE_TURN`        | 0    | 起始回合                                                                     |
| `BOT3_CUTSAVE_UNTIL`       | 0    | 结束回合（0 = 不设上限）                                                     |
| `BOT3_CUTSAVE_FOG`         | 关   | 只在迷雾房武装（机制本身非迷雾专属，此门禁仅为可测性保留）                   |
| `BOT3_CUTSAVE_CLOSING`     | 关   | 收尾相位（`closing.js`）接管计划时停发（`planner.js` 把 `closeIn` 传进本层） |
| `BOT3_CUTSAVE_BEHIND`      | 0    | 只有己方兵力 <= 对手兵力 × 该系数时才武装（0 = 不限）                        |
| `BOT3_CUTSAVE_BEHIND_LAND` | 0    | 同上，按实地格数比                                                           |
| `BOT3_CUTSAVE_SHARE`       | 0    | 孤岛兵力必须 >= 己方兵力 × 该百分比（0 = 不限）                              |

两点实现细节（都是本轮测出来的）：

1. **门禁必须读排行榜，不能读格子**。迷雾房里 `units` 只带可见格子的兵力，用格子求和会系统性低估对手，`BEHIND` 于是在迷雾房永不放行（实测：格子求和版本下 10 个被改变的局全在**全图**单线，迷雾 +1 胜直接丢掉）。现在 `planner.js` 把 `self.army / enemyArmy / self.land / enemyLand` 与 `closeIn` 一起传进 `cutApply`，格子求和只是兜底。
2. **`SHARE` 是唯一的硬分离器，而且不干净**。逐局追踪（临时 `BOT3_CUTSAVE_TRACE` 钩子，已移除）显示：两个退化真的触发点孤岛只占己方兵力 **8.2% / 8.9%**（`anti/随机/全图单线` 种子 2 座位 0 的 515 兵局 42 兵、`apex/迷宫/全图单线` 种子 2 座位 0 的 360 兵局 32 兵），而保留下来的收益局孤岛占比从 **2% 到 27%** 都有。所以 `SHARE` 不是结构分离器，它只是「小口袋不值得一回合」的经济阈值：抬到 10% 能同时关掉那两局，代价是让 5 个收益局回到基线结果。

### 结论与建议

- 严格门禁（Relay 目标格 >=65%、其他格 >=50% 且不低于基线）**现在可以满足**：`MAZEFOG3 + CUTSAVE(MIN=10, BEHIND=1, SHARE=10)` 零退化格（并行分支修掉迷雾迷宫层那 1 局之后），全量 +19 胜。
- 帕累托前沿（屏幕 768 局）：`BEHIND=1` 563 胜 / 2 个 -1 格；`BEHIND=1 SHARE=10` 562 胜 / 0 个 -1 格。用 1 胜换掉 2 个退化格是这一轮唯一值得的交换；无门禁的 563 胜带 6 个退化格，不是备选。
- **本层仍然默认关闭**（AGENTS 要求不静默默认开启）。要采用时用上面那一行环境变量；`CLOSING`、`FOG`、`TURN`、`BEHIND_LAND` 实测都不改善该组合（`CLOSING` 与 `BEHIND+SHARE` 叠加后逐局 0 变化），保留为可复现的负结果开关。
- 修复不是「把 ±1 局搬走」：`BEHIND` 把 6 个退化格压到 2 个是因为它改变了**一类局面**（领先时不再花回合连孤岛），`SHARE` 只是最后 2 局的经济阈值。剩余风险见下。
