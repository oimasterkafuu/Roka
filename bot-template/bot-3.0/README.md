# Bot(3.0)

Bot(3.0) 以 [`relay-bot`](../relay-bot/) 为基础框架，参考 [`bot-2.0`](../bot-2.0/) 的 1v1 结构，目标是在官方小图（1v1 标准尺寸，`0.34`）上继续提升对 Apex、Anti-Human、Bot(2.0) 与 Relay 的实战胜率。首个提交是 Relay 2.16.0 策略的完整副本，作为后续改动的基线。

当前主线已合入迷宫走廊相位、单线收尾纵队、迷雾单线层、第 7–13 轮的默认层（先涂地、影子预测、迷雾迷宫、反向救援、群岛、抢地、沼泽惩罚 + 武装斩杀），第 15–16 轮的多线扩张形状层与持续施压层，并同步上游 relay 的 opening/reinforcement pricing 与多线 burst 移除。最终小图 1v1 基线为 **1739/254/55（84.9%）**，较第 13 轮基线 1688/299/61 **+51 胜且逐格零退化**；Relay 单线 8 格全部 >=65%，多线 8 格 50.0%–93.8%（random 明牌 68.8%、arch 明牌 65.6%、med 明牌与迷雾均 93.8% 达标，四格仍是镜像残余，证据见 [MULTI.md](MULTI.md) 与 [ROUND17-ROUNDUP.md](ROUND17-ROUNDUP.md)）。完整矩阵见 [BASELINE.md](BASELINE.md)，后续方向见 [NEXT.md](NEXT.md)，第 15–16 轮汇总见 [ROUND16-ROUNDUP.md](ROUND16-ROUNDUP.md)。

## 结构

- `strategy.js`：托管/CLI 共用入口，维护座位、队列序号、帧同步与心跳。
- `planner.js`：逐 Tick 决策；处理扩张、建造、战役、救援与迷雾记忆。
- `opening.js`：前 24 Tick 的等待、汇兵与并行扩张规划。
- `single-front.js`：单线对手评估、补给切断、围城与集结路线。
- `maze.js`：迷宫（走廊）层：地图判定、集中式前线规划器的推迟启用与可选的走廊换线纪律。
- `closing.js`：小图单线终局的收尾层（见下节），默认开启。
- `land.js`：沼泽重图抢地层：按地形结构（沼泽占比）判定地图，在明牌单线、我方地盘落后于对手时停用收尾漏斗（默认开启，`BOT3_LANDFIRST=0` 关闭；`BOT3_LAND_CAPTURE`/`_PAINT`/`BOT3_LANDBURST`/`BOT3_ISLANDCROWN` 为实测为负、默认关闭的可开关项，见 [LAND.md](LAND.md)）。
- `kill.js`：单线斩杀层（第 13 轮起默认开启，但只在影子层 `armed`——已证明对手是被重放的 relay 规划器——时生效；`BOT3_FINISH=0` 关闭，`BOT3_FINISH_ARM=0` 去掉门控，见 [SHADOW.md](SHADOW.md)）。
- `multi.js`：多线 focus 层（burst 已随上游移除而默认关闭；默认关闭，`BOT3_MULTI=1` 开启，见 [MULTI.md](MULTI.md)）。
- `mshape.js`：多线房间扩张形状层（第 15 轮，**默认开启**，`BOT3_MSHAPE=0` 回基线）：把继承的 16 单上限放开到全部候选、让「会废掉一次占领的合并」排在占领之后（引擎里合并目标当 Tick 不能出手，`strategy.js` 又会在队列非空时跳过规划）、并在已大幅领先或走廊按实测退场；实测默认值 `SLOTS=64 STEAL=100 LEAD=110`：Relay 多线 8 格 512 局 +10 胜、全量 2048 局 +6 胜且零退化；与 `mhalf.js` 组合后全量 1702/290/56（+14，零退化），因此默认开启（见 [ROUND15-MSHAPE.md](ROUND15-MSHAPE.md)）。
- `mhalf.js`：多线房间「持续施压」层（第 16 轮，**默认开启**，`BOT3_MHALF=0` 回基线）：按我方领土到前线环的跳数场重新排序**自己的合并**——把「补满一个本 Tick 无法出兵、补后达到 3 兵（全冲推出的下限）」的合并排到最前（跳数越深扣分越多），并把补不满的合并压到占领之下；另有一条默认关闭的 `retain` 模式策略（半兵保留滚动驻军）。实测（`mshape` 之上）：种子 1–16 的 256 局 `129 → 136`（+7，random 明牌 21/32 达标），独立半区 17–32 回吐 `-6`，合计 512 局基本持平；但全量 2048 局 `1702/290/56`（83.1%，相对上一版基线 +14、逐格零退化，组合基线成立），因此随 `mshape` 一起默认开启；`retain` 模式因「占领至少需要三兵」在结构上惰性，保持默认关闭（见 [ROUND16-MHALF.md](ROUND16-MHALF.md)）。
- `mtune.js`：多线评估的自博弈调参层（第 17 轮，默认关闭，`BOT3_MTUNE=1` + `BOT3_MTUNE_JSON` 开启）：用一个 JSON 球（14 个加性分数权重 + 7 个 mshape/mhalf 旋钮，默认值即第 16 轮数值）统一拥有多线房间的占领/敌格/合并/拱形/切断/脉冲/王冠行军/防御价格与订单上限、领先门控，只改分数、不新增机制；配套 `scripts/tune-bot3-mtune.cjs` 在真实引擎上做可续跑的坐标下降/随机重启搜索（种子 1–8 训练、9–16 选择、17–32 确认）。实测：107 个候选在 128 局训练块上只散布在 60–70 胜，冻结权重 1–16 为 `136 → 140`、17–32 为 `119 → 120`、全量 2048 局净 0 胜（4 格 +7 / 4 格 −7），每格均未达 65%，因此默认关闭（见 [ROUND17-MTUNE.md](ROUND17-MTUNE.md)）。
- `m2ply.js` + `msim.js` + `mqueue.js`：多线精确搜索层（第 17–18 轮，**默认开启**，`BOT3_M3PLY=0` 关闭；`BOT3_M2PLY=1 BOT3_M3PLY=0` 复现第 17 轮两 Tick 版本）：`msim` 是引擎的精确一 Tick 仿真（增长、多线队列的链式/成环/建造背压、推兵与 1:1 互损、连通性减半与衰减、主城斩杀），`mqueue` 重放 relay 的规划器预测它下一 Tick 的整批指令（整盘逐格校验门，任何漂移即停用），`m2ply` 用三 Tick 仿真 + 「剩余脉冲折现」的地盘估值（外加兵力、主城安全、环宽、断链）在规划器候选之外补充它从不提出的横向合并与一对多灌兵，超过余量才改选。实测：512 局明牌多线 51.4% → 57.6%，验收屏 256 局 136 → 143（random 明牌 68.8%、med 明牌 65.6% 过线），全量 2048 局 1702 → 1709 且零退化，8.2ms/Tick、改选率 30%（见 [MSIM.md](MSIM.md)、[ROUND18-MSEARCH3.md](ROUND18-MSEARCH3.md)）。
- `bankgate.js`：几何门控后方主城层（第 19 轮，**默认开启，仅明牌房间**，`BOT3_BANKGATE=0` 关闭）：第 18 轮的后方金库机制 + 实测几何门控（前线无中立地可拿、后方盆地存得住兵、地盘不领先），把 hop≥3 的搁浅兵力汇成主城；随机图实测为「管道」因此被排除，迷雾房间交给 `mcrown2.js` 的迷雾版（分工比任一层全房间实测 +4 胜）。
- `mcrown2.js`：沼泽迷雾后方主城层（第 19 轮，**默认开启**，`BOT3_FOGBANK=0` 关闭）：只在迷雾房间且全图沼泽占比 ≥30%（迷雾下仍可见）时启动，把 hop≥3 的搁浅兵力沿 BFS 场一格一格汇入后方金库，50 兵建指挥所、再 50 兵升主城（+1 兵/Tick）；实测迷雾多线 65 → 82 胜（med 迷雾 30/32），其余 62 格 0.0pp（`BOT3_MCROWN2=1` 是第 18 轮不分迷雾的全图版本，实测 3 格退化）。第 20 轮（默认关闭，`BOT3_MCROWN2_SHALLOW`）：在沼泽占比 ≥55% 的岛上把汇兵带从 hop≥3 缩短到 hop≥2——群岛的金库被第一次 50 兵建城抽干，能补满主城的那部分兵力恰好浅一跳；`relay/archipelago/fog/multi` 19 → **24/32**（独立半区 18 → 21），其余 15 个 Relay 格逐局一致、Relay 半区 +5 胜，见 [ROUND20-ARCHFOG.md](ROUND20-ARCHFOG.md)。
- `mtune.js`：多线评分自博弈调参层（第 17 轮，默认关闭，`BOT3_MTUNE=1` + `BOT3_MTUNE_JSON`）：一个 JSON 球持有 14 个加性评分权重与 7 个层旋钮，配合 `scripts/tune-bot3-mtune.cjs`（128 局 16 秒、内容哈希可续跑）；最佳冻结集在样本内 +4 但样本外 +1、全量净 0，因此保留为工具而不是默认路径（见 [ROUND17-ROUNDUP.md](ROUND17-ROUNDUP.md)）。
- `fog.js`：迷雾单线前线瞄准/柱状推进层（默认开启，`BOT3_FOG=0` 关闭）。柱状推进的「先涂地」封顶默认开启（`BOT3_FOG_PAINT3=0` 回到 round-4 基线，见 [BOT3_FOG.md](BOT3_FOG.md)）。
- `fog-multi.js`：迷雾多线 burst 土地竞赛门控（多线 burst 移除后默认关闭，`BOT3_FOG_MULTI=1` 开启，见 [BOT3_FOG.md](BOT3_FOG.md)）。
- `fog-maze.js`：迷雾迷宫层：走廊目标场、中立格涂色加分、柱状推进、换线纪律与王冠经济门控（第 11 轮起默认开启，`BOT3_MAZEFOG3=0` 关闭，见 [BOT3_MAZE.md](BOT3_MAZE.md)）。
- `fog-oracle.js`：迷雾情报层：用未迷雾的排行榜反推对手内部驻军密度、剩余中立格与王冠数（默认关闭，`BOT3_FOGORACLE=1` 开启，见 [BOT3_FOG_ORACLE.md](BOT3_FOG_ORACLE.md)）。

- `bot3.test.cjs`：短局穷举、峡谷、迷宫判定、收尾层、斩杀层、多线/迷雾层与协议回归。

## 收尾层（closing）

`closing.js` 只在小图（`<= 800` 格）、单线、对手已铺开至少 6 座主城、我方兵力不低于对手 1.35 倍、且没有主城受威胁时接管计划：停建主城/指挥所与升级，把帝国兵力汇聚到最大的那一股，这股部队在“打穿剩余路径所需兵力”（`required`）足够前原地等待、其余兵力持续汇入，足够后沿主城距离场推进；主城攻击与两 Tick 围城仍保持更高优先级。威胁出现时该阶段自动暂停并交还防御评分（非一次性闩锁）。

- 开关：`BOT3_CLOSING=0` 恢复基线行为（逐局与基线完全一致）。其余可调项：`BOT3_CLOSING_BOARD`、`BOT3_CLOSING_TURN`（默认 60）、`BOT3_CLOSING_CROWNS`、`BOT3_CLOSING_FLOOR`、`BOT3_CLOSING_PUSH`（默认 0=关闭）、`BOT3_CLOSING_PUSH_SCALE`（默认 0.75）。
- 迟速双段：新 relay 在约 110 Tick 就铺开到 6 座主城，旧 120 的启用点整整晚一个阶段；`BOT3_CLOSING_TURN` 降到 60 并用满量矩阵验证零退化。实验开关 `BOT3_CLOSING_PUSH=250 BOT3_CLOSING_PUSH_SCALE=0.75` 会在该 Tick 后让主柱按 `required` 的比例提前投入（把“等凑齐整条路径的兵力”改成“后期按比例压上”），在 16 种子 relay 矩阵上多 1 胜（`relay/random/clear/single` 17 -> 18）且没有任何格子退化，但默认关闭，仍走纯 `required` 门控。
- 迷雾单线不走这一层：planner 只在 `clearSerial` 房间（非多线、非迷雾）调用 `closingUpdate`，迷雾单线由 `fog.js` 的集结-突袭教条负责。
- 新引擎最终 2048 局中，`BOT3_CLOSING_TURN=60` 的收尾层贡献 +6 胜（round6 1615/374/59 → 最终 1621/367/60），逐格零退化；旧引擎的 1490→1519/414/115 仅作历史记录。

## 终结层实验（默认关闭）

`kill.js` 移植了 Bot(2.0) 斩杀层「证明本 Tick / 短 ETA 可斩杀且不会先被斩杀」的思路，但没有照搬 Apex 的图搜索：

- 反向需求场：从所有可见敌方王冠多源 Dijkstra，`need[目标] = 驻军 + 1`，己方锚点按 `need - (army - 1)` 递减、敌方格按 `need + 驻军 + 1` 递增；一次搜索覆盖全部王冠。
- 逐 Tick 复算：每 Tick 只发射最佳路线的第一步，并按 `present - 1` 的全推模型正向重算，防守方增长按到达 Tick 计入（对进攻方保守），所以路线被堵就自然停止发射，不会沿旧计划行军。
- 竞速：仅当目标是敌方最后一冠时，反手用同一搜索估计对手斩杀我方王冠的最短 ETA，要求 `我方 ETA + margin <= 对方 ETA`。
- 切断与增援：路线上的己方割点若在到达前被敌方威胁击穿则否决；目标格还必须吃得下 `threat`（四步内敌方可达兵力的衰减值）的增援。
- 迷雾下只允许攻击可见王冠、只走可见格，绝不按记忆中的空驻军规划。

### 实测结论（配对比较，均对 `baseline-results.jsonl`）

| 配置                        | 规模                        |           Δ胜率 |
| --------------------------- | --------------------------- | --------------: |
| 默认（ETA 7 / 富余 25）     | 2 种子全矩阵 256 局         |          +0.4pp |
| 默认，仅 relay+anti         | 4 种子 256 局               |          −0.8pp |
| `MARGIN=0`（允许同速对杀）  | 4 种子 256 局               |          −1.2pp |
| `SURPLUS=1, ETA=10`（激进） | 4 种子 256 局               |          −1.6pp |
| 仅斩首（ETA 7）             | 4 种子 256 局               |           0.0pp |
| 仅斩首（ETA 7）             | 8 种子 512 局               |          −0.4pp |
| `ETA=2, SURPLUS=25`         | anti 单线三格 16 种子 96 局 |          −1.0pp |
| `ETA=2, SURPLUS=60`         | anti 单线三格 16 种子 96 局 |           0.0pp |
| `ETA=4` / `ETA=7` 仅斩首    | anti 单线三格 16 种子 96 局 | −4.2pp / −5.2pp |
| `ETA=7, SURPLUS=25`         | anti 单线三格 16 种子 96 局 |          −8.3pp |

- 越长、越激进的斩杀路线越差：relay 的启发式已经覆盖相邻与围城窗口，而 3 Tick 以上的「可证明」路线会被对手增援、割断补给或反向偷冠惩罚（与 Bot(2.0) 测到的 `maxEta:1` 结论一致）。
- 16 个 Relay 镜像格在**所有**配置下都是 0.0pp：对称局面里双方斩杀 ETA 相同，竞速校验必然否决，层无法制造系统性优势；`MARGIN=0` 只是让双方互相偷冠，净收益为零。
- 因此交付形态是「能力 + 开关 + 记录」，默认保持 planner 原路径不变（与基线逐局一致）。若后续要真正提升单线终结，方向应是经济/囤兵政策（例如地中海单线长期囤积上千兵力却不进攻），而不是更长的斩杀路线。

## 王冠经济门控（第 11 轮，默认开启）

第 11 轮修掉了迷雾迷宫层唯一的退化局（`anti/迷宫/迷雾单线` 种子 9 座位 0：基线 277 Tick 胜 → 层 580 Tick 负）。逐 Tick 追踪显示它不是土地或兵力问题，而是**经济政策**：对手把 43~48 格地盘换成 20+ 座王冠（排行榜兵力 450 → 968 → 3775），本层只有 2 座。

修复不再靠退场判据，而是**从排行榜兵力读出对手王冠数的下界**：王冠是唯一每 Tick 产出的地块，所以非成长 Tick 的兵力增量就是 `王冠 - 战损 - 建造`；取最近 16 个增量的**中位数**（最大值会被「孤军合流加倍」这种一次几十点的事件污染）。当对手下界 >= 4 且我方 <= 3 座王冠时，本层把整帧交回普通规划器（谓词而非锁存，我们自己建起王冠后会重新接管）。

实测（16 种子，每格 32 局）：`anti/迷宫/迷雾单线` 29/32 → **30/32**（与基线逐局一致），`Relay/迷宫/迷雾单线` 21/32 不变；32 局 Relay 迷宫迷雾单线里该中位数从没有超过 3，退化局在 t100 就是 4。全量 2048 局 **1636/352/60（79.9%）对基线 1621/367/60**，64 格无任何一格胜率低于基线，Relay 有 4 格 >= 65%（迷宫/随机/地中海 迷雾单线 + 迷宫全图单线）。`BOT3_MAZEFOG3` 因此改为**默认开启**（`=0` 关闭捆绑）；`BOT3_FOG_MAZE_ECON=0` 只关闭门控。细节与扫描表见 [BOT3_MAZE.md](BOT3_MAZE.md)「第 11 轮」。

## 组合实验（第 8 轮，默认不开）

第 8 轮把两个第 7 轮的正向机制（`BOT3_MAZEFOG3` 迷雾迷宫层、`BOT3_CUTSAVE` 反向切断）放到同一张 16 种子 Relay 网格上组合，并对每个退化格做定向修复。**两个机制在各自的格子外都只是 ±1 局噪声，无法同时满足「Relay 每格 >= 65% 且零退化格」，因此默认配置保持不变（全部开关仍为关闭）**。

归因（分别单独实测；¹ 迷雾迷宫层只作用于迷宫图，`planner.js` 的每个钩子都以 `mazeFogRoom = isMazeBoard && enabled` 为前置，所以 1627 是「四对手迷宫 512 局实测 +6 胜」加上「非迷宫格不可变」推算得出，未单独跑完整全量）：

- 迷雾迷宫层的全部改动都落在迷宫图（`planner.js` 的每个钩子都以 `mazeFogRoom = isMazeBoard && enabled` 为前置），四对手迷宫 512 局为 425W/76L/11T 对 419/83/10（+6 胜），唯一退化是 `anti/迷宫/迷雾单线` 1 局；非迷宫 12 个 Relay 格在 16 个网格配置里逐格完全相同。
- `CUTSAVE` 的收益是 Relay 随机 +6、迷宫 +1，以及 anti 三个全图单线格各 +1；代价是 `anti` 两个迷雾单线格与 `apex` 两个全图单线格各 -1 局。

定向修复全部实测为负（细节见 [BOT3_MAZE.md](BOT3_MAZE.md) 与 [CUT.md](CUT.md)）：迷雾迷宫层 30 个变体里只有 `CAPTURE=100` 与 `TURN=80` 能修掉 anti 那 1 局，代价是 Relay 迷宫迷雾单线掉到 19/32（59.4%，低于 65% 门禁），且同一个 `CAPTURE=100` 让 `apex`/`bot-2.0` 的迷宫迷雾单线各丢 1 局——1 局级的偏移在四对手矩阵里只是被搬到别的格子。`CUTSAVE` 的定价扫描（`CAP=90`、`GAIN=1`、`MIN` 6/10/20/30）也全部保留至少 2 个退化格。

结论（第 8 轮）：**默认仍然一个都不开**。若要按「Relay 门槛优先」取舍，唯一推荐的单开关是 `BOT3_MAZEFOG3=1`（Relay 迷宫迷雾单线 50.0% -> 65.6%，全量净 +6 胜，代价是 anti 1 局）；组合（`MAZEFOG3 + CUTSAVE _MIN=10`）净 +23 胜、Relay +12 胜，是「总量最优但带 5 个 -1 局」的选项，需要维护者明确接受这 5 局。

### 第 11 轮：定位门禁让组合通过严格门禁（默认仍关闭）

第 8 轮修不动的是 `CUTSAVE` 的 5 个退化格；第 11 轮改为筛**触发局面**（`BOT3_CUTSAVE_BEHIND` 只在兵力落后时武装、`BOT3_CUTSAVE_SHARE` 只在孤岛 >= 己方兵力 10% 时武装，门禁读排行榜而不是可见格子），于是：

| 配置                              | 屏幕 768 局胜 | `CUTSAVE` 退化格 |
| --------------------------------- | ------------: | ---------------- |
| `MAZEFOG3=1`（参照）              |           558 | —                |
| `+ CUTSAVE MIN=10`（第 8 轮形态） |           563 | 6 格各 -1        |
| `+ BEHIND=1`                      |           563 | 2 格各 -1        |
| `+ BEHIND=1 SHARE=10`（本轮推荐） |           562 | **0**            |

推荐组合 `BOT3_MAZEFOG3=1 BOT3_CUTSAVE=1 BOT3_CUTSAVE_MIN=10 BOT3_CUTSAVE_BEHIND=1 BOT3_CUTSAVE_SHARE=10` 的全量 2048 局为 **1640/339/69（80.1%，+19 胜）**：63/64 格 >= 基线且 >= 50%，唯一退化格是迷雾迷宫层自己的 `anti/迷宫/迷雾单线` 29/32（并行分支修复后归零），Relay 侧 `迷宫全图/迷宫迷雾/地中海迷雾/随机迷雾` 四格分别为 65.6% / 65.6% / 68.8% / 68.8%。多线 32 格逐格 0.0pp。完整扫描、归因与复现见 [CUT.md](CUT.md)「第 11 轮」；本层仍然默认关闭（不静默默认开启），采用时用上面那一行环境变量。

## 运行

```sh
pnpm install
BOT_SERVER=http://127.0.0.1:23333 BOT_ROOM=room BOT_TOKEN=token pnpm start

```

服务端托管入口为 `require('./strategy').attachStrategy(socket, options)`。目录名 `bot-3.0` 会由 `src/server/server-bot-manager.ts` 自动发现，无需额外注册。

## 评测

先构建真实引擎，再分批运行验收矩阵；每批保持前台运行，结束后合并：

```sh
pnpm run build
SEED_FROM=1 SEED_TO=4 WORKERS=4 OUT=/tmp/bot3-1.jsonl SUMMARY=/tmp/bot3-1.json node scripts/evaluate-bot3-baseline.cjs
SEED_FROM=5 SEED_TO=8 WORKERS=4 OUT=/tmp/bot3-2.jsonl SUMMARY=/tmp/bot3-2.json node scripts/evaluate-bot3-baseline.cjs
SEED_FROM=9 SEED_TO=12 WORKERS=4 OUT=/tmp/bot3-3.jsonl SUMMARY=/tmp/bot3-3.json node scripts/evaluate-bot3-baseline.cjs
SEED_FROM=13 SEED_TO=16 WORKERS=4 OUT=/tmp/bot3-4.jsonl SUMMARY=/tmp/bot3-4.json node scripts/evaluate-bot3-baseline.cjs
node scripts/summarize-bot3-baseline.cjs /tmp/bot3-1.jsonl /tmp/bot3-2.jsonl /tmp/bot3-3.jsonl /tmp/bot3-4.jsonl
pnpm run eval:bot3:compare -- /tmp/bot3-1.jsonl
```

`compare-bot3-baseline.cjs` 按 `(对手, 地图, 迷雾, 多线, 种子, 座位)` 与基线配对，可传入完整结果或两种子快速筛查；对 Relay 每格要求 65%，其余每格要求 50% 且不低于配对基线，未达标时退出码为 1（`NO_GATE=1` 仅报告）。

也可一次性跑完整 16 个种子。`OPPONENTS`、`MAPS`、`MODES`、`TICKS` 与 `SEED_PREFIX` 可覆盖默认值；`MODES` 的三位依次为大小图、迷雾、多线，基线使用 `000,001,010,011`。评测器只加载各对手的公开托管入口，并使用正式引擎的地图、增长、调度与战斗规则。
