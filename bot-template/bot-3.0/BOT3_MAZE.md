# 迷宫层实验记录（Bot(3.0) 小图 1v1）

本文件记录 Bot(3.0) 首个针对迷宫地图的策略层：动机、实现、开关与配对评测结果。基线见 [BASELINE.md](BASELINE.md)。

## 问题定位

迷宫（`map_mode: maze`）是小图上唯一“走廊化”的地图：生成器先铺满山脉，再用生成树打通，最后加约 3% 额外开口。山脉占比约 50%（随机图约 12%），所以走廊里每个房间只有一两个出口。

逐 Tick 回放基线（`bot3-baseline-2`，对手 Relay，全图/单线）可以看到两类失效：

1. **免费兵流**。全图单线每 Tick 只能下发一个指令，而 `planner.js` 的 `single` 分支（`clearSerial && turn >= 28`）会把整帧用在 1~3 个兵的房间互送：入口 tick 的候选分数是 `own && defense[j] < defense[i]` 的 600+，永远压过真正的推进。结果是 900+ 兵的皇冠一直不动，一兵一兵地往堆上浇。
2. **互锁超时**。双方都是同一套策略时，两边各自在自己那棵子树里做同样的浇兵动作，谁也不肯把主力压进走廊，于是 1000 Tick 互锁（基线 512 局迷宫中有 38 局超时，Relay 迷宫/全图/单线一格 32 局里 12 局超时）。

这两点在迷雾与多线格子里不出现：那两种模式走的是通用路径（`single` 只在 `clearSerial` 即非迷雾、非多线时启用），迷宫成绩本来就高（对 Bot(2.0) 96.9%~100%）。

因此本轮不改任何开放地图的评分，只做一件事：**在迷宫上推迟集中式前线规划器**，让走廊先走通用扩张路径（迷雾/多线格已经在用的那条），到 250 Tick 之后再交回前线规划器收尾。

## 实现

新增 [maze.js](maze.js)，`planner.js` 只加两处钩子：

| 位置           | 内容                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| `chooseOrders` | `const maze = isMazeBoard(b)`；`single = clearSerial && turn >= (maze ? SINGLE_FROM : 28)` |
| 指令落地循环   | `BOT3_MAZE_LANE=1` 时调用 `laneBlocked()` 做走廊换线纪律（默认关闭）                       |

- `isMazeBoard(b)`：`grid_type === 201` 的比例 > 30%。随机图山脉约 12%、迷宫约 50%，阈值落在两者之间，且迷雾下山脉始终可见，判定不受迷雾影响。
- `SINGLE_FROM`（默认 250）：迷宫上集中式前线规划器的最早启用 Tick。
- 走廊换线纪律（默认关闭）：移植 Bot(2.0) `mazeActionGuard` 的边历史——记录最近使用的移动边、反向边与 3/4 Tick 短期冷却；反向、连续第三次同边、冷却中的边在候选选择时跳过，但“仍在朝目标推进的回撤”、夺皇冠、吃掉 16+ 兵的切入、真实救援不会被拦。

## 开关

| 变量                    | 默认  | 含义                                         |
| ----------------------- | ----- | -------------------------------------------- |
| `BOT3_MAZE`             | 开    | `0` 完全关闭迷宫层（回到基线行为，用于对照） |
| `BOT3_MAZE_SINGLE_FROM` | `250` | 迷宫上前线规划器启用 Tick                    |
| `BOT3_MAZE_LANE`        | 关    | `1` 打开走廊换线纪律                         |

## 未解决

- Relay 迷宫格 3/4 仍为 50.0%/46.9%/50.0%（多线与迷雾）。这些是镜像局且没有超时空间：镜像里同一张图的两局由地图/座位优劣决定，候选与基线逐局一致，只有真正强于克隆策略的战术才可能翻盘——需要 Bot(2.0) `mazeblitz` 那种量级的“筑垒—汇兵—压柱”层，而不是评分微调。
- 非迷宫门禁失败（Relay 全图各格 50%、Anti-Human 随机/地中海全图单线 25%~40.6%）与基线一致，属于本轮范围之外。

## 迷雾迷宫层（fog-maze，默认关闭）

第 7 轮把 `exp/bot3-mazefog2` 的迷雾迷宫层移植到当前基线上，并补上它留下的唯一退化格。源码见 [fog-maze.js](fog-maze.js)。

**动机**：迷宫 + 迷雾是唯一「两层都不管」的房间。`./fog` 默认排除走廊图（`BOT3_FOG_MAZE=0`），`./maze` 的集中式前线规划器只在 `clearSerial`（非迷雾）房间启用。剩下的只有一条没有目标场的通用扩张策略：`targets` 来自记忆中的对手主城，而迷雾视野只有半径 1，所以大多数时间 `goal` 全是无穷大，推进类评分全部失效。

**行为**（迷雾、单线、走廊图、`size <= 800`、`turn >= 38` 起）：没有记忆主城时，目标场取「可见对手前线 + 可通行树远端」；中立格前进涂色加分压过自身格合并；启用迷雾柱状推进（`columnAdvance` + `fogRequired`）；可选用迷宫换线纪律。`endTurn=450`、`known`（一旦记忆到对手主城立即交回）、`landCap=300` 三个退场门控维持原设计。

### 唯一退化格与四处未成功的修复

退化局是 `anti/maze/fog+single` 的种子 9 座位 0（基线 277 Tick 胜 → 580 Tick 负）。逐 Tick 追踪（每 5 Tick 记录占地、前沿中立格数、最大堆、指令）显示，它不是「前沿没有中立格」：第 100~580 Tick 前沿中立格一直有 3~5 个，我们的占地从 53 一路被吃到 19，对手从 49 涨到 91、兵力从 768 涨到 4032。层把主力留在走廊柱状推进（评分 1100+），原路径会把兵力集中到受威胁方向。

四个针对性修复全部实测为负（16 种子，配对）：

| 变体                                            | Relay 迷宫迷雾单线 | Anti 迷宫迷雾单线 | 结论                                                                              |
| ----------------------------------------------- | ------------------ | ----------------- | --------------------------------------------------------------------------------- |
| 纯层（默认）                                    | 21/32              | 29/32             | 参照                                                                              |
| `BOT3_FOG_MAZE_PAINT=120`（合并封顶，全前沿）   | 19/32              | 29/32             | 修不好，还丢掉 2 个 Relay 胜局                                                    |
| `PAINT=250`                                     | —                  | 27/32             | 更差                                                                              |
| `BOT3_MAZEFOG3=1`（PAINT=120 + `PAINT_FROM=8`） | 21/32              | 29/32             | 前沿 >= 8 中立格才生效：本引擎的退化局只有 3~5 个，规则**不命中**，逐局与纯层一致 |
| `BOT3_FOG_MAZE_DROP=12`（占地跌破纪录即退场）   | —                  | 28/32             | 层的早期扩张本身在赢其它 anti 局，中途退场亏更多                                  |
| `TURN=45 / 50 / 60`（推后启用）                 | —                  | 28 / 24 / 26      | 越晚越差                                                                          |

综合取舍：`BOT3_MAZEFOG3` 默认带 `PAINT=120, PAINT_FROM=8`（对归档分支记录的「60+ 中立格空转」形态布防，在本引擎的 16 种子矩阵里是空操作），`DROP` 默认 0（实测为负，保留为可复现的负结果开关）。整层仍**默认关闭**：它把 Relay 迷宫迷雾单线从 50% 抬到 65.6%（唯一达标路径），代价是 Anti 那 1 局（90.6%，仍远高于 50% 下限）——是否默认开启需要维护者按「Relay 门槛 vs 零退化」的取舍决定。

## 第 8 轮：组合网格与修复扫描（默认仍关闭）

第 8 轮把这层与 `BOT3_CUTSAVE` 组合在同一张 16 种子 Relay 矩阵上，并对本层唯一的退化格（`anti/迷宫/迷雾单线`，种子 9 座位 0：基线 277 Tick 胜 → 580 Tick 负）做了 30 个变体的定向扫描。完整组合网格、全量 2048 局与默认决定见 [README.md](README.md)「组合实验」一节；这一节只记录本层的扫描结果。

### 归因

| Relay 迷宫 全图 单线      | 21/11/0        | 21/11/0    |   0.0pp |

`CAPTURE=100` 在四对手迷宫屏幕上把退化格从 Anti 搬到 Apex 与 Bot(2.0)（各 24/32 对 25/32），说明这 1 局不是可修的偏差：对手共用同一张按种子生成的图，**地图形状无法把 Relay 与 Anti 分开**，能分开的只有对手行为，而 32 局/格的分辨率下任何价格微调都只是把 ±1 局搬来搬去。

结论：本层**保持默认关闭**。若要单开关换取 Relay 迷宫迷雾单线的 50.0% -> 65.6%，用 `BOT3_MAZEFOG3=1`（全量净 +6 胜，代价是 Anti 那 1 局）。
