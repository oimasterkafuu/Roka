# Roka 独立自对局机器人

自行实现协议、状态、移动与建造策略；运行机器人不依赖旧 strategy-bot。离线训练直接调用 `reference/src/game-engine.ts` 的真实规则。

## 在线运行

Node.js 18+，pnpm：

```sh
pnpm install --frozen-lockfile
pnpm test
BOT_TOKEN='你的令牌' pnpm start
# 指定房间：
BOT_TOKEN='你的令牌' node bot.cjs --room=abc
```

默认连接 `https://roka.oim.moe:444/`，进入 `bot` 房间，**不自动准备**，**从不设置倍速、地图类型或种子**。环境变量 `BOT_SERVER`、`BOT_ROOM` 可覆盖默认值。令牌只读取环境变量，勿提交仓库。

管理员 `oimaster` 在当前房间公开聊天中发送：

- `/ready`：切换自动准备；首次开启，再次关闭。开启后每次局间等待5秒；关闭会取消准备。
- `/room abc`：本局彻底结束后转入 abc；如果当前在局外则立即切换。阵亡不是整局结束，不会提前换房。重连保留当前房间和开关。

验证服务器提供的 `sender`，拒绝跨房转发和队伍消息；不从消息正文推断身份。服务端没有消息签名或用户类型字段，同名认证账户的区分需服务器保障。切换房间通过断开/重连释放旧席位。

机器人不修改设置，但参考服务器自身可能在 Bot 加入时关闭迷雾、局末更新种子，这是服务器行为。进程需持续运行，未安装开机自启。

## 策略

- 每tick只提交一个移动或建造；守城、可获胜斩首先于经济。
- 路径搜索使用引擎真实智能分兵公式，支持拓地、汇兵与孤立重连。
- 建造使用敌军路径距离与预计到达时间、山体阻挡、援军、余兵、回本视野、领土与产能目标，不再使用固定112/62门槛。建造费用50和孤立不可建是引擎硬约束。
- `bot/params.cjs` 定义14项可调参数及范围；`bot/champion.json` 保存经评估部署的版本；`BOT_PARAMS` 可指定其他JSON文件（顶层 `params`）。

## 本地自对局与进化

```sh
pnpm train --rounds=8 --seeds=3 --validation=8 --turns=2200 --workers=4 --suite=my-experiment --output=training/results/experiment.json
node training/benchmark.cjs
# 从已有候选继续；不会自动改写线上部署版本
pnpm train --resume=training/results/experiment.json --suite=new-seeds
```

`reference` 必须存在；首次离线使用 esbuild 将真实引擎打包并缓存在工作线程内存中，无网络、真实定时等待、回放写盘。每worker顺序推进真实tick，每局独立种子。两侧交换座位，在 random/maze/archipelago/mediterranean 四类图上对局。默认4个工作线程，可减少以控制本地负载。

每轮随机扰动3项参数，与当前冠军对局。晋级还需在独立训练种子上通过固定旧版本基线与分地图退化检查，防止只克制上一代。最后使用另一组留出种子报告，不将验证结果回灌本轮搜索。超时仅算平局，不按兵力冒充胜利。训练不会自动发布参数，保留人工审核关口。变更算法后应重新训练与验证，不复用旧分数。

当前是**进化式参数学习**，不是神经网络训练，也不是最优解求解器。单个基线、有限种子和双人全图可见场景的评估不能保证对所有人类、多队混战、大地图或迷雾都强。报告中的score为胜1/平0.5/负0，不是纯胜率。

## 持续集结与短程对抗

`bot/logistics.cjs` 为每局维护独立计划：实际敌前线优先，后方运输沿己方领地距离递减；根据闲置兵比例给予运输配额，紧急守城/斩首先行。按运输耗时计入敌方增长、可见援军和扣除自然增长后的集兵趋势，目标仍有效就持续补兵，不因固定计时到期换点。

经济计划优先升级已有指挥所，在后方总体资金能完成两阶段投资时可先花50建造、再调兵升级；产能邻接位置有集群加分，筹资与建造共用配额避免挤占进攻。威胁和增援仍是保守估计，不是读取对手意图。

`bot/tactics.cjs` 对最多8个候选、每个最多8种敌方应对作短程覆核，包含自然增长、先增援/后反击和有限预算的断供收益。它不是完整多人博弈树。线上与训练统一调用 `bot/policy.cjs`。

```sh
pnpm compare --seeds=3 --turns=2400 --size=0.8 --suite=independent-test --output=training/results/comparison.json
```

对照为冻结的上一版 `training/previous`，仅本地真实引擎高速模拟。报告记录胜负、截断未决、运输操作、建造次数和采样后方兵力占比。后方定义为距可见敌地曼哈顿距离超过3，不等同于所有后方兵力均无用。

## 一次性爆发期（26–50 tick）

`bot/opening.cjs` 独立评估开局：0–25 tick播种扩张，26–50 tick优先安全普通地拓展；决策帧t的命令在t+1增长后执行，新占领地从t+2开始享受增长。收益按剩余增长次数计算，不将沼泽或指挥所当成爆发经济地块。t<50时策略调度不提交建造，也不允许经济筹资抢占开局决策；紧急保城与可靠直接斩首保留优先级。t=50后恢复持续物流和经济投资，该窗口不周期性重复。

长程规划同时计入抵达前敌主城/普通地自然增长，减少静态兵力看似足够、到达时不够的进攻。

```sh
node training/burst-eval.cjs --workers=6 --seeds=6 --turns=1800 --size=0.5 --suite=新的种子批次 --output=training/results/新报告.json
```

脚本默认与冻结的 `training/preburst` 对照，记录25/50/100/200 tick领土与兵力、真实引擎接受操作、胜负和超时未决；拒绝混合策略哈希或覆盖旧报告。6线程是本次本机测试配置，不意味着占满或最适合所有M3 Pro型号。当前仍为启发式/短程搜索，没有神经网络权重。

## 指挥塔用途与断供防守

`bot/architecture.cjs` 为建造与物流提供同一风险门槛：后方塔以继续筹资升级皇冠为目标；有团队锚点连接价值、附近受威胁且无法安全升级的瓶颈位置可保留低成本塔。皇冠评估纳入至少8步到达窗口内的敌军总量和增长，避免只看最近弱敌，也避免把整个地图远处所有兵力当成立即威胁导致永不建设。风险消退或当前驻军足以覆盖保守预算后才升级。它仍是有界估计，不保证敌人绝无反抗可能。

`bot/interception.cjs` 对最多8个可夺取的连接节点检查敌同队全部可见锚点；只有真实失去所有连接的、尚未孤立的敌兵才计入减半收益。未知组件或计算预算不足则放弃。连通重算晚于所有玩家移动，因此不以本tick尚未发生的减半来拯救已经能被直接攻陷的皇冠。

## FFA：统一威胁与开战约束

`bot/ffa.cjs` 每tick基于真实队伍、可达路径、增长后的攻击兵力及最近40tick实际夺地识别威胁；至少三个存活阵营时启用单目标主动进攻。主目标通常保持60tick，仅目标失效或近皇冠强入侵提前切换。同队敌人视为一个阵营。其他玩家仍是真实敌人，所有留兵、风险计算仍考虑他们，不伪装成队友。

规划器与后方集结共享允许攻击的阵营，所有最终攻击再统一检查；近锚点的有效自有地增援或可胜清敌优先于经济，断供防守仍需满足当前tick安全。爆发期开局扩张保持优先，但不因此随意攻击第三方。威胁方可以被反击，并非绝不允许同时应对多人。

目前FFA验证为多方局面单元测试和策略出口测试，离线arena仍为双人完整对局；不得将双人回归成绩当作FFA多人胜率。

## 皇冠冗余与提前回防

单皇冠、至少20地且tick>=100时，经济目标至少两个皇冠（不代表立刻无条件建成）。安全后方已有塔可按筹资后的潜力立项，实际升级仍以真实兵力检查风险；移除32tick固定过期，保护在途资金，军事预算不再无限吞没经济预算。远程“斩首”标签不阻止投资，真实立即斩首/救城优先。

`bot/defense.cjs` 对每座皇冠计算最长12tick的可见敌军路径，计入阻力和增长，按援军到达时限选择截击或己方路径增援。孤立敌人不当作可移动威胁，不从另一受威胁皇冠抽空兵力。未知路径不作已知通路，不能保证预测迷雾突袭。该机制为路径威胁预测，不是读取对手的真实计划。

## 防守调度与建设收口

非紧急回防不再把路径上原有兵力冒充新增援军；首步和净贡献必须达到动态门槛，普通1–2兵搜刮让位。按实际执行回执限制五tick最多两次非紧急回防，威胁未推进或缺口未改善时冷却。确实能扭转三tick内失守的少量急救保留，可胜截击优先。

后方新塔必须在该格先集齐100兵加安全余量，再执行建塔/升级两阶段；已有未升级塔则不新开经济塔项目，相邻自有塔旁也不落新塔。先聚兵再花钱，不再把分散的远处资金当作立即完成皇冠的承诺。危险瓶颈塔仍是独立用途。

## 大图皇冠集群与多源攻城树

大图扩产目标按安全后方地块与扣除留守后的兵力推算，不再默认封顶5座；默认绝对上限20（maxCrowns范围2–40）。近敌土地不计入安全产能基地，资金不足不强行扩产。后方仍先完成已有指挥塔、集中两阶段费用，不重复铺半成品。

`bot/campaign.cjs` 在军力占优、没有紧急威胁时针对FFA主目标的皇冠构建持续攻势：多兵源在自有连通区组成朝向汇集点的BFS树，叶子先汇入父节点，父节点再向根移动。预算包括逐步调兵耗时、敌增长、路径防御与附近增援，达到预算才出击。攻城调兵优先普通物流，并通过统一防循环和目标约束；每四tick仍允许一次可行建设。

这不是全局最优路径树或精确同时行动博弈求解，仍可能因保守预算或动态防守等待。当前未启动线上机器人。

## 汇兵树收益剪枝（更新）

只为按兵力分布动态筛出的高收益兵源建立运输路径并集；按预计送达兵力/新增操作数挑选，优先共享路径，不把全领地2兵细枝纳入。路径上格子仅作为中继，最多选择12个源、64条边以限制计算与等待。前线集结点现有兵力足够时，按立即进攻的到达时间报价并出击，不等余下后方分支全部送到。

皇冠建设不再使用maxCrowns硬上限（该参数仅保留兼容旧文件）。安全大图按安全格数和可支付的两阶段投资决定继续扩产；局部皇冠邻接有加分，但过密区域降分，引导形成若干小产能集群。已有指挥塔优先升级的约束保留。

## 滚动汇兵与孤军救援

每tick重算前线终点、有效兵源和收益剪枝后的汇兵树，仅执行一步；缓存对手目标和防抖偏好，不再长期排除曾经供兵的格子。前线够兵立即推进，防循环仍依据实际执行回执。

`bot/rescue.cjs` 按孤立组件评估六步以内的重连路径，计入mode0、敌增长、移动留兵、反击风险与替代攻击机会成本；重连收益按届时兵量乘二而非恢复原始兵力估算。预算内收益足够才救，大团优先，弱团或高损失放弃。每tick重算路线，救援优先经济/普通攻势，紧急保城更高。该搜索是有预算启发式，并非全局最优证明。

### 边界稳推与动态分兵（2026-09-25）

中期（turn >= 50）新增 `bot/frontline.cjs`，对普通进攻统一做末端安全审查，包括战术、切断、救援、攻城、物流产生的敌/中立捕获；真正紧急的主城救援保留例外。开局 26–50 爆发扩张不受这层中期约束影响。

- 先从现有前沿部队寻找可以立即拿下的边界，不以集齐所有兵源为开战条件。比较多个攻击方向，但每 tick 仍只有一个合法动作，不声称同时执行多路攻击。
- 半兵能打赢且源点/占领后驻军足够时优先半兵；全冲只有安全预算通过才允许。协议 `mode:1` 是自动分兵理论值的一半，不是总可动兵的精确 50%；没有新增协议模式。
- 安全预算检查可见两步敌军机动、源点留兵、目标反击，以及最多六层后方补给链。已孤立敌军不计机动威胁，但其守军依然参与捕获计算。公式仍严格保留服务器的真实自动分兵规则。
- 攻城集结默认只预算下一格，不再为穿过整片敌区预先筹足兵力；已有其他接敌集群不会被主动抽作兵源。每帧重新选方向，不固定等待两三个集群就位。
- 保留每四 tick 的有效建设机会。友方运输仍使用原模块模式，不把这次改动扩大为全局运输规则重写。

限制：这是保守的局部启发式，不是完整的多方行动顺序搜索。两步威胁按兵力上界累计，可能高估反击；补给检查有深度限制，不保证识别所有远距离割断。尚未实现两个或三个独立集群的显式分区调度，而是保留现有前线、逐帧选择当前可攻方向。需要持续用实际对局检验是否过度保守或仍有物流抢占。

本轮验证：`pnpm test` 312 项通过。`training/results/frontline-v1.json` 为对 `precampaign` 的 8 局真实引擎双人本地测试（四地图、换边、1200 tick）：0 胜、1 负、7 局超时未决。不能据此宣称实力提升；推进收尾偏慢是明确后续风险。该结果不是完整 FFA 验证，也不是与上一版 rolling-rescue 的直接同种子比较。未启动线上 Bot。

### 就近筹兵与及时出击修正（2026-09-25，覆盖上一节调度描述）

定位并修复了具体停攻路径，而非笼统归因为“保守”：

1. 后方脆弱连接曾无条件否决攻击。现在按实际出兵量审核：普通军队仍拒绝危险深入；已知局面下，占领后即便减半仍超过可见敌军三倍，且源点留下足够兵力时，可以执行一步推进。不是全面取消补给安全约束，亦不能保证未知敌情下安全。
2. 中期可执行边界进攻提前到普通切断、救援、建设和集兵之前，仅真正紧急保城优先。取消可攻击时每四 tick 强制让给建设；无合适攻击时再进行补给和经济。
3. 攻城筹兵先使用 1–3 步内有效来源，避免远方巨堆抬高来源门槛；近源不足后再远调，选够缺口停止扩树。前线实际已足够时不等待树。
4. 普通军事物流也优先近源，并按距离评估运输效率。附近皇冠若不能全抽，则尝试真实 mode1 半兵，保留所需守军，不再直接跳过附近皇冠。

验证：322 项测试通过，覆盖 75 万前线对 3 万敌军的脆弱补给合成局面、连续四次有效进攻、1–3 步皇冠优先、近源耗尽远调。该合成局面不是用户实际对局回放。

最终真实引擎报告 `training/results/nearby-offense-v2.json`：沿用 `frontline-v1` 测试种子、地图及历史对手，8 局为 0 胜 / 2 负 / 6 超时未决（此前 0 / 1 / 7）。未证明整体实力提高，仍需处理策略组合与收尾问题。acceptedActions.attacks 同时包含友方运输，不可作为进攻频率。未启动线上 Bot。

### 前线缺口必须触发后方补给（2026-09-25）

新增优先级高于普通微操/建设的 `militaryOnly` 物流入口（仅中期）：可安全攻击先攻，否则存在真实前线兵力缺口时，持续从连通后方运输。不要求看见敌皇冠，不受攻城模块总军力 1.4 倍门槛、普通物流隔 tick 配额、经济整格保护限制。近源是优先级而非最大距离；无近源则选远源。少量新生兵不能不断抢占远处有效兵源。禁行边纳入反向 BFS，可走更长合法路线；此通道不以候选提交冒充执行、不登记虚假运输配额。

330 项全量测试通过。新增统一策略连续测试：前线2000对敌3000、近处均1兵、后方1600兵且无可见敌皇冠，总兵力低于1.4倍，连续六步输送后第七步攻击；另验证后方不足也先运、近源后远源、绕禁行边、提案未执行不扣配额。连续fixture按其一维场景的增长/分兵/战斗规则推进，不是完整真实引擎对局，也不是用户回放。本轮未进行新的胜率对照，未启动线上进程。

### 反击交换、短期重连与腹地运输

中期统一末端检查现允许补给源可守、无脆弱后链且不属于深插的有效边界交换：敌人未来能够夺回目标不再一票否决；敌格实际守军须达到出兵量15%且至少5兵，避免为微小收益大量送兵。仍要求出兵能拿下目标，不包含主动撞击无法攻下的守军。

一步快速重连若桥可承受当前单支邻敌反击、被救大团有下一tick的可行进攻、折扣后净收益仍足够，可以接受多支敌军未来合流再次切断风险。该机会在普通后方集兵前审核，但当前有效进攻与紧急保城仍优先。不假设接通当tick孤立兵就能行动；这是局部启发式，不保证多队联合攻击顺序安全。

中期己方安全腹地运输统一采用mode2（全冲留1）；有两步内机动威胁或未知侧翼的来源不按腹地处理，保留原保护分兵。开局策略保持原样。

334项全量测试通过，报告 `training/results/exchange-reconnect-tests.log`。本轮未运行新胜率评估，未启动线上Bot。

### 正面后援与一轮补给预算

源点两步威胁搜索现在避开本次攻击目标：必须穿过目标才能抵达源点的后援属于正面反击，不算绕切源点。浅边界、已知且补给无脆弱后链的可捕获敌格，不再因敌目标后援强或目标守军不足出兵量15%而停攻。真实侧路、深插和紧急保城仍受安全约束；仍未加入无法捕获目标的主动消耗撞击，也不假设人类会延迟反应。

军事补给首次触发时固定一轮预算：守军、增长、有限局部后援（上限守军5%）、约10%余量。例2000对3000约筹到3300。正在进行的批次会让同一前线在小批到账后继续补足，不抢占其他前线攻击，也不在已有可用攻击时新开预算阻止它。目标失效、达标、无有效来源、turn倒退或16tick到期解除；每步路径重算。预算是估计，不保证一次攻势成功。

343项测试通过，含目标后援10000对源1000仍可正面出击、真实侧路保留防守、3100未达3300时继续批次补给及原本能打不新开等待。本轮未跑新增完整胜率对照，未启动线上Bot。结果：training/results/attack-batch-tests.log。

### 防守误动员与决策延迟诊断

`[决策]` 原来每20turn采样，不能据此认定只每20turn行动。客户端新增每20次实际计算汇总：发送数、空动作、平均/最大耗时、收到的更新跳号；单次>=50ms记录慢决策。发送仍非服务端执行，跳号也不等同网络丢包。新局重置统计。

远程>3tick预防汇兵须有同一既有皇冠方向的相邻两拍敌军实际推进证据；静止、原地长兵、新造皇冠导致距离变短不再触发持续回防。近距离致命救援与可胜截击仍保留。防守路径搜索使用地形BFS距离严格下降的最短路DAG，不枚举重复绕路；因此不是完整敌方绕路策略模拟。已执行的mode1/2/half回执均计入原防守限额，避免统一运输转换模式后漏记。统一策略在有进攻/补给可用时不再预先计算基线全局寻路和截击。

本机性能构造测试：24x24、18己方皇冠、288可见敌格，旧防守中位163.16ms，修改后5.62ms（10次测量）；脚本 training/defense-benchmark.cjs。完整本地基准8局9600ticks，旧131.23秒、新42.71秒，吞吐约73→225ticks/s。整体行为变化导致所经历局面不同，不能把约3倍吞吐直接当作同局面延迟改善；不能保证所有在线地图都低于125ms。报告在training/results/*latency-benchmark*.json与defense-performance*.json。

本轮无线上连接，没有实际对局回放，因此不宣称已重现用户整场往返循环或修复所有空动作。连续静止敌/逼近后停步/新增皇冠/回执配额测试与客户端每帧发送测试用于限定回归。

### 相邻皇冠空动作修正

直接攻冠分支位于合法性/FFA/隔离检查之后、普通长期推进预算之前。按下一tick增长及真实模式计算可捕获时，不再被后方未知、普通深插/脆弱补给预算拒绝；保留来源皇冠的可见绕切留守，不假设攻下一冠就消灭敌人。源点分兵相关邻格未知时只用出兵量确定的mode2。皇冠候选优先入围，直接攻冠不受普通补给批次等待影响；紧急救城仍优先。

空动作每20次计算窗口增加 `[空动作诊断]`，包含前线候选数、孤立来源数、过滤计数以及最多4个数值样例。该信息为有限候选局部诊断，不是完整棋盘回放或所有模块的拒绝证明。

355项测试通过。复现了 `[101,102,202]`、兵力 `[100,70,0]`、目标后方未知时旧策略全部null，而新版实际选出攻击的构造局面；未获得用户原局棋盘，不能认定原局就是同一根因。未启动线上Bot。报告 training/results/direct-crown-tests.log。
