# Roka

Roka 是一个实时方格领土战争游戏（generals.io 类），使用 TypeScript + Fastify + Socket.IO 实现。

## 运行

```shell
pnpm install
pnpm run dev
```

或构建后运行：

```shell
pnpm run build
pnpm run start
```

其他常用命令：`pnpm run lint`、`pnpm run format`、`node --test bot-template/apex-bot/test/*.test.cjs`（apex 规则/控制器单测）、`node bot-template/apex-bot/training/benchmark.cjs`（四地图固定种子真实引擎基准，未结束局计平局）、`pnpm run test:bot`（bot 集成测试：用临时数据目录启动服务器，接入两个 `bot-template/random-patch-bot` 自动开局对局；dist 缺失时会自动构建）、`pnpm run test:server-bot`（服务端托管策略 Bot 冒烟测试：超管 API 启动 simple-strategy-bot 与 random-patch-bot 对局，并启动 anti-human-bot 校验模板枚举/自动准备/房间唯一/组队开关）、`pnpm run test:lobby-guards`（开局/换绑守卫回归：全员同队拒绝开局、同名人类不抢 bot 席位、断线重连恢复、大地图面积、只剩 bot 时房间设置重置且对局中不触发）、`pnpm run test:presence`（统一在线状态测试：presence-service 假时钟单元测试 + 真实服务器集成测试，覆盖活动刷新/过期判离线/去重计数/bot 不计入）、`pnpm run test:map-generation`（华夏九地区确定性、联通性、岛屿保留和基本可玩性测试）、`pnpm run test:huaxia-season`（上海时区年度窗口边界测试）。

其他常用命令：`pnpm run lint`、`pnpm run format`、`node --test bot-template/apex-bot/test/*.test.cjs`（apex 规则/控制器单测）、`node bot-template/apex-bot/training/benchmark.cjs`（四地图固定种子真实引擎基准，未结束局计平局）、`pnpm run test:bot`（bot 集成测试：用临时数据目录启动服务器，接入两个 `bot-template/random-patch-bot` 自动开局对局；dist 缺失时会自动构建）、`pnpm run test:server-bot`（服务端托管策略 Bot 冒烟测试：超管 API 启动 simple-strategy-bot 与 random-patch-bot 对局，并启动 anti-human-bot 校验模板枚举/自动准备/房间唯一/组队开关）、`pnpm run test:lobby-guards`（开局/换绑守卫回归：全员同队拒绝开局、同名人类不抢 bot 席位、断线重连恢复、大地图面积、只剩 bot 时房间设置重置且对局中不触发）、`pnpm run test:deploy-update`（部署更新 UX 回归：webhook 排队广播、排队期禁开局、宽限到期按当前名次清算、dry-run 恢复）。

启动后访问 `http://localhost:23333/` 并注册账号。

华夏系列地图与地图示例仅在每年中国时区 10 月 1 日至 10 月 7 日（含全天）开放，10 月 8 日自动关闭，按 `Asia/Shanghai` 判断且不写死年份。回放重建不受年度窗口影响。

## 游戏规则

与旧版 / generals.io 的主要差异：

- **Tick**：1 Tick = 0.5 秒，速度 speed 0.5~4 只缩放 Tick 间隔。
- **生产**：主城（crown）每 Tick +1；普通地块与指挥所（city）每 50 Tick +1（仅正常状态）；沼泽、中立格不生产。
- **爆发期**：第 26~50 Tick 为全局爆发期，正常普通领土每 Tick 额外 +1；客户端表现为地图最外圈红色边缘（逐渐减弱）。
- **推兵三种模式**：普通 WASD 全兵（只留 1 兵看守，其余全部推出）；Z 半兵（一次性，按智能分兵理论推出减半取整，执行后失效）；Shift+WASD 智能分兵（保留 = 其他三方向非己方相邻格「兵力-1」之和 + 1，目标方向不参与计算；不消耗 Z）。优先级 Shift > Z > 普通。
- **攻击判定**：攻击兵力严格大于防守兵力才占领；未严格大于（含相等）时进攻失败但双方互损——进攻方损失全部推出兵力，防守方等量减兵（最低到 0，归属/建筑不变）。占领后防守兵力全灭，新兵力 = 攻击兵力 − 防守兵力（占领有损耗）；占领建筑 = 摧毁建筑（变为普通地）。占领敌方最后一座主城 → 该玩家出局，其剩余领土不转移、不折半，全部沦为孤军并逐渐衰减消亡。
- **光标**：WASD 后光标总是移动到相邻非山脉格，即使该次推兵无效（兵力 ≤ 1、选中非己方格等）——无效推兵不入队、不显示箭头，光标保持可移动。
- **建造**：X 建指挥所（己方正常普通地块、兵力 ≥ 50、已连通己方主城/指挥所，消耗 50）；C 升级主城（己方正常状态的指挥所、兵力 ≥ 50，消耗 50，立即获得每 Tick +1 生产与锚点资格）；在普通地块上按 C = 连续两步（先建指挥所、下一 Tick 升级主城），角标同时显示指挥所与皇冠。建造与推兵共用同一队列（每 Tick 每玩家最多执行一条队列操作）；入队只校验地形，归属/兵力/连通在执行时校验，不满足则自动跳过并继续执行后续操作。沼泽/山脉禁止建筑。
- **连通与孤军**：己方格经连续己方格（普通地或己方沼泽）四方向连通到己方任意主城/指挥所 = 正常领土，否则断链为孤军。断链瞬间兵力减半（⌊n/2⌋，1 兵保持为 1）；孤军不可选中/推兵/建造/生产、无爆发加成；断链后前 5 回合（10 Tick）为宽限期，只快速闪烁不衰减，第 6 回合起每回合（每 2 Tick）衰减 max(1, ⌈当前兵力×5%⌉)，归零变中立；孤军连通组件重新接回己方主城/指挥所时立即恢复正常且每格兵力 ×2。孤军格在客户端闪烁（宽限期快速闪烁，衰减期常速闪烁），闪烁由全局时钟驱动，不受本地操作影响。
- **空格**：跳转选中到曼哈顿距离最近的己方主城（距离相同取建立较早者）；镜头仅在目标不在当前视野内时才拖动居中，已在视野内则保持不动。
- **胜负**：最后主城决胜制——失去所有主城即出局，存活至最后的队伍获胜。
- **掉线宽限期**：对局中网络断开后有 10 秒宽限期（1 倍速 = 20 Tick），期间不判挂机、不投降，刷新页面/重连即可恢复对局（服务端自动补发全量状态）；超过宽限期以「挂机」原因自动投降并转为观战。主动退出（返回房间 / 离开）不变，仍立即投降。
- **视野**：迷雾远征为房间可开关设置（默认关闭）。关闭时全图始终可见；开启后存活参赛者只能看到己方（含队友）格子周围一圈内的真实状态：视野外地块统一显示为「山 + 问号」未知占位（沼泽例外、始终可见），加暗色遮罩、不揭示真实地形与兵力；视野内地形正常显示，但敌方的指挥所与主城不显示建筑身份（只见归属颜色与兵力；中立城市照常）。服务端按视野过滤下发；观战默认全图可见，迷雾对局中观战者（含观战席与战败后）可通过底部「视角」选择器切换到任一玩家的队伍迷雾视野（与回放视角切换一致，纯显示层，存活参赛者不可切换），迷雾对局的回放默认全知视角、可切换任一队伍视角。迷雾对局的观战与回放中名称显示统一：组队局（存在 ≥2 人的队伍）观战视角的排行榜与视角选择器只显示队伍名「队伍 N」，非组队局照常显示用户名；参赛玩家自己的视角不受影响；回放为全知复盘，排行榜一律显示真实用户名（组队局仍按队伍合并展示、组行显队名）。房间内有 Bot 参战时迷雾强制关闭且不可开启。城市（指挥所）不由地图预置，只能由玩家建造。
- **地形**：山脉不可通行/占领；沼泽可占领可存兵，但永不生产、不可建筑、参与连通。
- **地图大小**：房间可开关设置（默认标准）。普通地图按参赛人数缩放；选择大地图后无论人数都使用 `MAX_TEAMS`（16 人）的最大基础比例再放大 2 倍，地图边长约为标准最大基础地图的 2 倍、面积约为 4 倍；大地图对局的回放按实际尺寸重建。地图示例始终使用普通地图比例。
- **华夏系列地图**：新增 `huaxia` 模式，可选秦、汉、唐、辽、宋、元、明、中国、台湾省九个地区，并支持 `map_region` 协议字段；旧值 `three-kingdoms` / `northern-dynasties` 仍归一为汉，其他未知值和缺省值回退为中国，旧值 `qing` / `hong-kong` 归一为中国。中国视口约为东经 73..135°、北纬 18..54°，用于覆盖中国大陆和台湾附近的自然地图视口，不代表精确国界。每个地区有独立的代表时期经纬度矩形（矩形面积仅是完整视口面积，不冒充历史疆域面积；可靠历史边界矢量未纳入，疆域面积明确为未知）。视口内整块矩形使用仓库内由 [Natural Earth 1:50m land v4.0.0](https://naturalearth.s3.amazonaws.com/50m_physical/ne_50m_land.zip) 转换的真实 WGS84 陆地多边形，来源为 [Natural Earth 公共领域许可](https://www.naturalearthdata.com/about/terms-of-use/)，因此西部陆地不会因超出某个中国轮廓而变海，离岸岛屿也保留并正常渲染；只有最大陆地连通块的平原加入出生池，其他陆块仍可见但不会出生。山脉/关隘是有地理依据的游戏化近似，除河西走廊、潼关、雁门关、剑门关、梅关外，还固定开放井陉、武关、子午道、大散关、夔门、湘桂走廊等小半径山间通道，避免整条山系被削平。`scripts/generate-huaxia-land.py` 保留下载、版本、URL、许可和简化过程，可再生小型数据文件。地貌和尺寸不读取种子，随机种子只影响既有 `selectRandomGenerals` 出生点选择。

## 平台功能

- 用户系统（注册 / 登录）；首个注册用户自动成为超级管理员（唯一，不可剥夺、不可封禁），可在后台管理页授予/撤销其他用户的管理员权限。
- 后台管理页 `/admin`（仅管理员可见入口）：用户列表（rating、注册/最后在线时间、角色、封禁状态）分页展示，顶部支持按用户名即时搜索并显示用户总数；支持按时长封禁（1 小时/1 天/7 天/自定义/永久）与解封；被封禁用户无法登录且已登录的连接会被立即踢下线，封禁到期自动解除；管理员之间不能互相封禁，超级管理员不受限制。超级管理员另有「策略 Bot」分区：指定已注册用户名、房间号并从服务端自动枚举的模板下拉框（`bot-template/` 下带 `strategy.js` 或 `server-bot.js` 的目录）中选择模板，即可在服务器进程内启动托管 Bot（内存临时令牌鉴权，跳过验证码），还可勾选该 Bot 房间是否允许组队；同一用户名最多运行一个 Bot，同一房间也只能运行一个 Bot。Bot 自动进房/准备、对局结束后自动重新准备、可随时手动停止；服务器重启后自动按原配置（相同用户名、房间号、模板与组队许可）恢复运行中的托管 Bot（状态持久化在 `data/server-bots.json`，用户失效/封禁或模板缺失时记警告跳过，手动停止即清除不再恢复）；托管 Bot 进房不当房主（房主保留给后续进房的人类用户或第三方 Bot）、豁免房间心跳踢出、不参与单会话顶号互斥；不允许组队的托管 Bot 所在房间禁止组队——Bot 进房时会强制关闭已开启的组队模式，且房主的开启请求会被服务端拒绝（房间消息提示，前端开关锁定）；允许组队的托管 Bot 房间不受此限，组队开关仍由房主自行决定（Bot 进房不自动开启组队）；组队模式下服务端不再按机器人/人类分池——进房默认分配到人数最少的队伍、换队请求不做修正、开启组队也不重排，队伍归属完全由成员自行决定（官方 anti-human-bot 固定首选 2 队，检测到人类同队会自主避让换队）。
- 策略 Bot 模板 `bot-template/simple-strategy-bot`：具备开局发育模拟规划/威胁推演/集结防御/风险感知路径打击/前线突破集结/积极皇冠建设/多源兵力汇集的综合策略（`strategy.js` 管线编排 + `bot/` 纯函数模块），并按双层危险场对咽喉格定量驻军、为被切断的孤军组织走廊救援或止损、行军有纪律（防抖防送兵、打击体检与无望集结弃打）；可独立运行（与 random-patch-bot 相同的 CLI 用法），其 `strategy.js` 同时被服务端托管运行复用。
- 策略 Bot 模板 `bot-template/apex-bot`：独立于其他策略模板的新一代纯函数策略，逐 tick 预演 mode 0/1/2、建设成本/连通、斩首与切断风险，带有限敌方反击评分和反往返护栏；可独立运行、被服务端托管，并通过 `node --test bot-template/apex-bot/test/*.test.cjs` 与四地图真实引擎 benchmark 验证。
- 策略 Bot 模板 `bot-template/anti-human-bot`：独立实现的 AI 机器人（自研协议/状态/移动/建造策略与离线训练管线，用法见其包内 `USAGE.md`）；CLI 默认自动准备（`BOT_AUTO_READY=0` 关闭，管理员聊天 `/ready` 仍可切换），经 `server-bot.js` 适配托管运行时自动准备并固定首选 2 队；组队模式下服务端不干预队伍归属，bot 检测到人类加入本队会主动避让到其他无人类队伍（首选 2 队 → 最小编号空队 → 纯 bot 队）；对局中有人格表现——全面领先时按综合局势（领土比/兵力差/连续拆建筑/累计踩冠/对手停滞等多触发器）说帝国时代 2 嘲讽风格的垃圾话（全局冷却 + 每局上限 + 概率门控，对方领土单 tick 暴跌时触发 wololo 彩蛋），陷入绝境且被对方「调戏」（能赢不收尾）时发 GG 主动投降；可在后台作为托管模板直接运行。
- FFA 与组队模式，统一 Rating（不区分 1v1 / FFA）；Codeforces 风格段位名字颜色。新手显示分仿 Codeforces 从 0 起步（按 1200 / 2^对局数 的 delta 逼近真实分），内部结算仍按 1200 初始分。组队结算时队伍分按人数立方加权（400·log10(n³·Σ10^(r/400))：人数优势是压倒性的，等分 1v2 期望胜率约 1/17、1v3 约 1/82；单人队即自身分），避免以少打多被视为均势局。
- 首页三栏布局：左侧个人信息、房间列表（状态列区分「游戏中 / 人数不足 / 准备进度」）与回放列表（自己参与的对局浅黄高亮）；中间「动态」feed；右侧公告（仅管理员可编辑，与动态同一条管线，支持 Markdown 与服务端渲染的 LaTeX）、Rating 排行榜（前 10，Unrated 不参与）与「刚刚在线」列表（最近掉出在线状态的前 8 位用户及其最后活跃的相对时间）。排行榜只展示最近 7 天内有活动的用户——最后活动（对局结算、任意有效请求等，与 presence 同源）距今满 7 天即暂时下榜，rating 数据保留，重新登录或有任意活动后立即回榜；长期停用的 Bot 账号同样下榜（天天对局的 Bot 经结算刷新不受影响）。
- **统一在线状态（presence）**：以「用户最近一次有效请求/动作时间」为唯一事实来源——任何已认证的 API 请求（`/api/online` 查询自身除外，避免在线状态自我维持、永不掉线）与任何 socket 事件（连接建立、对局操作、房间心跳、聊天等）都会刷新该时间。「在线」= 最近 **5 分钟**内有活动；「最后在线」= 该时间戳（后台管理页用户列表同步显示）；「在线人数」= 在线窗口内的去重用户数（同一用户多个标签页/连接只计一次）；无事件自然过期由服务端每 30 秒扫描判定。`lastSeenAt` 按每用户 60 秒节流持久化（掉线时兜底落盘一次），服务器重启后从落盘数据恢复在线状态。Bot 连接（`ROKA_BOT_TOKENS` 合成用户与服务端托管 Bot）一律不计入在线人数、不刷新「最后在线」。
- 顶栏实时展示当前在线人数（见上条统一模型）；通过 `home_online` socket 失效通知（上线/下线转换时触发，2 秒节流）驱动首页刷新，数据来自 `GET /api/online`。
- 回放可下载为原始 `.rpl` 操作流文件（仅几百字节，只有服务端能解码）；观看页直接下发 gzip 压缩后的转码二进制（服务端按回放 id 落盘缓存，首次观看后无需再重建整场对局），加载期间显示下载进度；首页回放面板支持「上传并查看回放」——POST 给服务器转码后播放，版本过旧或损坏会弹出「不兼容」提示，服务端库存的不兼容回放会被自动删除。回放观看页顶部显示参赛者列表（组队局同队成员逗号分隔、队伍间「>」分隔，队伍顺序为终局名次序——整队存活者在前、全灭队按队内最后死亡成员先后排序，与 rating 清算口径一致，迷雾组队局按队名显示，均不展示玩家配色色块）；首页回放列表的名次列同口径按队伍合并展示（同队一组、组间名次序，旧归档回放无队伍数据时回退为个人平铺）；组队局回放的排行榜按团队合并——每队一个条目显示团队总兵力并按总兵力排序，队内成员行显示真实用户名并按兵力排序附后；排行榜下方有局势统计图（兵力/领土随回合的平滑曲线、原始值浅色底层），当前回放进度以竖线游标指示，点击或拖动图面可跳转进度。

- 「动态」：类似推特的 feed，支持点赞、评论、编辑与删除（管理员可管理全部），评论同样可删除（评论作者本人或管理员），支持 Markdown 与服务端渲染的 LaTeX；发布有 30 秒冷却；URL 带页码可分享翻页位置。
- 个人主页 `/u/<用户名>`：Rating 历史曲线、注册天数、其动态与参与的对局回放。
- 房间内支持观战；非观战玩家中「我准备好了」超过半数（向下取整）时自动开始。组队模式下若所有参赛者处于同一队伍，服务端拒绝开局并在房间消息中提示调整队伍（否则对局一开始就只有一支存活队伍，会立即终局）。观战中（含战败后）底部显示「下局模式」选择器，可提前切换下一局的观战/参与身份，避免对局结束后被瞬间重开的下一局拉进场；战败弹窗在对局进行中显示「观战」（仅关闭弹窗继续观战），对局彻底结束后变为「返回房间」，正在观战的用户在终局时也会再次弹出结算弹窗提示返回房间。
- **房间心跳检测**：房间准备阶段客户端每 30 秒上报一次心跳；超过 600 秒（10 分钟）无心跳的成员被服务端自动移出房间并跳回首页。对局进行中不检查心跳（对局断线仍走 10 秒宽限期）；`ROKA_BOT_TOKENS` 鉴权的 bot 连接豁免。
- **只剩 Bot 自动重置房间设置**：房间内有 Bot（第三方 bot 令牌或服务端托管）时，若所有人类成员都离开（断开连接或心跳超时被移出）、房间只剩 Bot，准备阶段的房间设置会自动重置为新建房间的默认值（地图类型/种子/倍速/组队/迷雾/地图大小全部回默认，种子重新随机），Bot 留在房内继续待命不被踢出。边界：观战席（队伍 0）的人类仍算人类占用，不触发重置；对局进行中不触发——若人类在对局中离开，等服务端对局结束回到准备阶段时才会重置；没有 Bot 的普通房间人走光后不触发（下次有人进房本就按新房间重建默认配置）。
- **浏览器通知**：登录后首次访问首页或房间页时，若浏览器通知权限尚未决定，会先弹解释窗说明用途（新玩家进房、游戏开始、有人上线或建房），由按钮手势申请权限；拒绝后不再打扰，解释窗每个浏览器最多弹一次。页面在后台时，房间内新玩家加入、游戏开始、首页有人上线或创建新房间都会弹系统通知；同一用户多个后台标签页通过 Notification `tag` 与 localStorage 时间戳互斥保证只弹一次。浏览器不支持 Notification 时静默跳过。
- **部署更新 UX**：GitHub push 触发自动部署时，若有对局在跑则进入「更新排队」状态——广播 `deploy_queued` 事件且 `room_update` 携带 `update_queued`：排队期间禁止开新局（开始按钮禁用并提示「系统即将排队更新，请稍等」），进行中的对局页面顶部显示「系统即将更新」警告横幅；120 秒宽限期（`ROKA_DEPLOY_GRACE_MS` 可覆盖）内玩家可继续打完，最后一局结束立即部署，到期仍未结束的对局按当前排行榜名次直接清算（正常结算给分并存档回放）后重启。重启期间页面由 Service Worker（`static/sw.js`）接管，显示「正在更新」提示页并轮询等待、服务恢复后自动刷新；更新失败（或 `ROKA_DEPLOY_DRY_RUN=1` 演练）时解除排队状态恢复正常。
- 实时聊天框跨房间同步。聊天用户名前的玩家色块按「在房间且参战」门闸显示：跨房转发的消息（房外人）与观战席成员不显示色块；对局中仅排行榜内且未淘汰的参赛者显示其分配颜色，房间准备阶段仅参赛席成员显示座位颜色。该色块是局内分配色（`.cN`），与用户名本身的 rating 颜色（rt-*）职责分开：全站用户名统一经 `static/username.js` 组件渲染——rating 颜色 + 点击跳个人主页，接口不带颜色的位置（回放列表、对局排行榜、聊天、房间成员等）经 `GET /api/user-colors` 批量补色（用户名→colorClass 全局缓存，未上榜/未定级降级 rt-unrated）。
- 玩家配色可读性：`.c0~.c17` 每个配色类同时声明背景色与文字色（按 WCAG 相对亮度取黑白中对比度更高者），排行榜姓名格等任何以玩家配色作背景的场景自动获得可读文字色。
- 教程分文字版（`/tutorial`）与互动版（`/tutorial/interactive`）两步。
