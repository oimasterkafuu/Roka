Roka 机器人开发协议

本文档与服务端实现（src/server.ts、src/game-engine/）逐条核对， 人类和 AI 都可以直接照着写出一个可用的 bot。仓库： https://github.com/oimasterkafuu/Roka

1. 快速开始

仓库内置参考实现 bot-template/random-patch-bot：它加入房间、自动准备、维护本地全图缓存，每回合随机挑一个合法动作发送 attack。建议先把它跑通，再在其状态机之上替换决策逻辑。

获取 token

登录有验证码，bot 无法自动登录。先在浏览器登录，然后从开发者工具的 Cookie 中复制 auth_token 的值（即登录 JWT）。

环境变量

BOT_SERVER 服务端地址，默认 http://127.0.0.1:23333。
BOT_ROOM 必填。要加入的房间号。
BOT_TOKEN 必填。上一步复制的 auth_token Cookie 值。
BOT_TEAM 组队模式下的目标队伍号，默认 1；非组队模式会被规整为参赛。
BOT_AUTO_READY 默认 1（自动参赛并准备）；设为 0 关闭。
BOT_ACTION_DELAY_MS 每回合决策后的发送延迟毫秒数，默认 120。 
cd bot-template/random-patch-bot
pnpm install
BOT_SERVER=http://127.0.0.1:23333 BOT_ROOM=your-room BOT_TOKEN=your-auth-token pnpm start

2. 连接与鉴权

Socket 地址 与站点同源，Socket.IO 默认路径 /socket.io/。
transport 服务端支持 websocket 与 polling。
鉴权字段 握手优先读取 auth.token（即 Cookie auth_token 中的 JWT）；未提供时回退读取握手 Cookie 里的 auth_token。
Bot 专用令牌 服务端可用环境变量 ROKA_BOT_TOKENS（格式 "token1:username1,token2:username2"）配置合成 bot 账号：握手 auth.token 命中表项时直接以对应用户名放行，无需注册。
鉴权失败 连接被拒绝，客户端收到 connect_error（消息如「未登录或登录已失效。」）。
身份标识 set_id 连接后服务器下发 set_id（字符串），值为当前 socket id 的 MD5。后续在 room_update.players[].sid、init_map.player_ids 与 update.kills 中都用这个 ID 标识自己。
单会话限制 同一用户名同时只允许一个 socket：新连接成功后，该账号的旧连接会被服务端直接断开（顶号）。 
// JS 连接示例（socket.io-client）
const { io } = require('socket.io-client');
const socket = io(BOT_SERVER, {
  transports: ['websocket', 'polling'],
  auth: { token: BOT_TOKEN }
});
socket.on('set_id', (id) => { /* 保存为自己的 client id */ });

3. 房间阶段协议（开局前）

3.1 Client → Server

join_game_room { room: string }。房间号服务端限制长度 1..15；建议只使用 [0-9A-Za-z_-]。
change_team { team: number }。0 表示观战；1..16 表示参赛/队伍号。非组队模式下，非 0 会被规整为参赛。
change_ready { ready: boolean }。仅参赛者有效，且仅在房间未开局时生效。
change_game_conf 可选字段 patch：speed（0.5~4）、allow_team（bool）、 map_mode（random|maze|archipelago|mediterranean）、map_token（最长 32）。 仅房主可改。

3.2 Server → Client

room_update 房间状态快照： { speed, allow_team, map_token, map_mode, in_game, players, ready, need }。
room_update.players[] 每项为 { sid, uid, team, ready }：sid 为该玩家 socket id 的 MD5；uid 为用户名；team 为 0（观战）或队伍号； ready 为准备状态。
ready / need 当前已准备人数 / 开局所需人数。need <= 1 时不会开局。
starting {}。满足开局条件后广播，表示即将进入对局，随后收到 init_map。
chat_message 聊天消息：{ sender, color, text, team }。color=0 时通常是系统消息。

4. 对局阶段协议（开局后）

4.1 开局事件 init_map

n / m 地图行数 / 列数。格子下标 idx = x * m + y（行优先）。
player_ids 所有玩家的 MD5 SID 数组。用 set_id 在其中查找下标（从 0 开始）， 你的 owner id = index + 1；查不到即为观战。
general [x, y]，你自己的主城坐标；观战者为 [-1, -1]。

4.2 回合事件 update

整体结构 { grid_type, army_cnt, isolated, lst_move, leaderboard, turn, kills, surrender_progress, game_end, is_diff, replay? }
turn 半回合计数（前端显示为 Math.floor(turn/2)）。1 Tick = 0.5 秒（速度 1x），speed 0.5~4 只缩放 Tick 间隔。
is_diff = false grid_type、army_cnt、isolated 都是长度 n*m 的全量数组，按行优先展开。
is_diff = true grid_type/army_cnt/isolated 均为 index-value 对： [idx0, val0, idx1, val1, ...]。机器人需要在本地缓存全图并增量合并 （isolated 在差分帧中可能为空数组，表示本帧无孤军状态变化）。
isolated 取值 0 正常；1 断链宽限期（断链后前 5 回合 / 10 Tick，只闪烁、尚未衰减）；2 衰减期（第 11 Tick 起每回合 / 每 2 Tick 衰减 max(1, ⌈兵力×5%⌉)，归零变中立）。
lst_move { x, y, dx, dy, half, mode, op, skip }。表示服务器已执行的最近行动（用于客户端队列确认）。op：'m' 推兵、'b' 建成指挥所、'c' 升级主城（后两者 dx=dy=-1）。 无动作时为 {-1,-1,-1,-1,false,0,'m'}。skip 为本 Tick 被执行操作之前因条件不满足被自动丢弃的队首操作数（无执行时为本 Tick 全部丢弃数）；失效操作会被服务器直接移出队列，后续操作在同一 Tick 继续尝试执行。
leaderboard[] 每项结构：{ team, uid, army, land, class_, dead, id }。class_ 可为 ''、'afk'、'dead'。
kills Record<sid_md5, killer_name>。当你被击败时，键为你的 set_id。
surrender_progress Record<owner_id, ratio>，ratio 范围 0..1，用于渲染投降衰减效果。
game_end true 表示该帧为终局帧。
replay 可选字符串，仅在终局附近出现，表示回放 ID。

4.3 格子编码（grid_type 线上编码）

0..49 普通地块，owner id = code（0 表示中立空地）。服务端内部记为 0。
50..99 指挥所，owner id = code - 50（内部 -1）。只能由玩家建造（build 操作，相当于 X 键，消耗 50 兵），地图不再预置；与普通地块一样每 50 Tick +1 兵（不享受爆发期加成），是连通锚点。
100..149 主城（将军），owner id = code - 100（内部 -2）。每 Tick +1 兵；失去所有主城即出局。
150..199 己方沼泽，owner id = code - 150（内部 2）。不产兵、不可建造，但参与连通。
200 可见空地（中立）。
201 可见山脉（内部 1），不可通行。
202 / 203 / 205 （已废弃）旧版战争迷雾编码。现已无战雾，服务器不会下发。
204 可见中立沼泽。

army_cnt 与 grid_type 同维度。没有战争迷雾：update 始终携带全图真实状态（全图可见）。

4.4 规则要点（与旧版 / generals.io 的差异）

  • 主城每 Tick +1 兵；普通地块与指挥所每 50 Tick +1（仅正常状态；指挥所不享受爆发加成）。
  • 第 26~50 Tick 为全局爆发期：正常普通领土每 Tick 额外 +1。
  • 无战争迷雾：全图始终可见，update 始终为全图真实状态（202/203/205 迷雾编码已废弃）。
  • 城市（指挥所）不再由地图预置，只能由玩家建造：X 建指挥所消耗 50 兵，C 升级主城再消耗 50 兵。
  • 攻击兵力必须严格大于防守兵力才能占领；未严格大于（含相等）时进攻失败但双方互损：进攻方损失全部推出兵力，防守方等量扣除（最低到 0，归属与建筑不变）。
  • 占领有损耗：占领成功后目标格新兵力 = 攻击兵力 − 守军兵力；被占领的指挥所/主城会被摧毁（降级为普通地块）。
  • 攻下敌方最后一座主城 → 该玩家出局，残余领土不再转移给攻击方，全部沦为孤军（不触发断链减半），随后按孤军规则逐渐衰减至中立。
  • 兵力无上限。
  • 连通与孤军：与己方所有主城/指挥所断开的领土成为孤军（见 update.isolated ），断链瞬间兵力减半（⌊n/2⌋，1 兵保持为 1）；前 5 回合（10 Tick）为宽限期（只快速闪烁、不衰减），第 6 回合（第 11 Tick）起每回合（每 2 Tick）衰减 max(1, ⌈当前兵力×5%⌉)，归零变中立；重新连通立即恢复且兵力 ×2。被切断的领土会持续衰减，扩张时务必保持连通。

5. 对局内可发送操作

attack { x, y, dx, dy, mode, half }。坐标均为 [row, col]。 (x,y) 是起点，(dx,dy) 是目标，要求四邻接。推兵量由 mode 决定：2 全冲（只留 1 兵看守）、1 半兵（智能分兵理论推出量减半取整，一次性）、0 智能分兵（为其他三方向的非己方相邻格保留「兵力-1」之和 + 1）。half 保留作兼容（half=true 等价 mode=1）。
build { x, y, op }。op='b' 建造指挥所（相当于 X 键），op='c' 升级主城（相当于 C 键），均消耗 50 兵。与 attack 共用同一队列，每 Tick 每玩家最多执行一条队列操作。入队只校验地形（普通地块），可排在队列很靠后的未来位置； 执行时才校验归属/兵力/连通，条件不满足会自动跳过（通过 lst_move.skip 告知丢弃数量），不会产生消耗。在普通地块上连发 b + c 两条即可两 Tick 后建成主城（相当于在普通地块按 C 键）。
clear_queue 清空当前玩家待执行操作队列。
pop_queue 删除队尾一条待执行操作。
send_message { text, team }。team=true 表示队伍频道。
surrender 投降并转观战。
return_room / leave 退出对局返回房间。服务端会回 left。

6. 增量帧合并示例

// 已知 n, m 和本地 fullGrid/fullArmy/fullIsolated（长度 n*m）
function applyDiff(pairs, target) {
  if (!Array.isArray(pairs)) return;
  for (let i = 0; i + 1 < pairs.length; i += 2) {
    target[pairs[i]] = pairs[i + 1];
  }
}

function applyUpdate(frame) {
  if (frame.is_diff) {
    applyDiff(frame.grid_type, fullGrid);
    applyDiff(frame.army_cnt, fullArmy);
    if (frame.isolated) applyDiff(frame.isolated, fullIsolated);
  } else {
    fullGrid = frame.grid_type.slice();
    fullArmy = frame.army_cnt.slice();
    fullIsolated = (frame.isolated || new Array(n * m).fill(0)).slice();
  }
}
提示：
  • 任何时刻都维护一份全量缓存，避免只依赖 diff 帧。
  • 收到 is_diff=false 全量帧时，用它重置本地状态。

7. 常见坑

  • 单会话顶号：同一用户名新连接会顶掉旧连接。bot 与浏览器同账号并存时会互相挤掉，建议给 bot 单独注册账号（或使用服务端 ROKA_BOT_TOKENS 合成账号）。
  • 队列节流：每 Tick 每名玩家最多执行一条队列操作。一帧内连发多条 attack/build 只是入队，不会立刻全部生效；规划节奏时按 Tick 计算。
  • 推兵模式优先级：按键上 Shift（智能分兵，mode=0）> Z（半兵，mode=1）> 普通（全冲，mode=2）。注意：不显式传 mode 且 half=false（或省略）时，服务端会按 mode=0 智能分兵处理——旧式 { x, y, dx, dy, half: false } 并不等于全冲；要全冲请显式传 mode: 2。
  • 操作确认：服务端不回 ACK，用 update.lst_move 对照本地队列： skip 条队首操作被丢弃后，本 Tick 执行的那一条与 lst_move 匹配。
  • 孤军不可操作：isolated != 0 的格子不可推兵、不可建造，推兵校验会直接失败。
