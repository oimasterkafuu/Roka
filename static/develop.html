Roka 网站开发

Roka 是实时方格领土战争游戏（TypeScript + Fastify + Socket.IO，前端为无构建原生 JS）。本页是与仓库代码核对过的开发指南：项目结构、本地流程、检查命令、提交与部署约定。仓库： https://github.com/oimasterkafuu/Roka

1. 贡献流程

  1. 在 GitHub 上 fork 仓库到你自己的账号。
  2. clone 你的 fork，并创建一个只聚焦单一主题的分支（feat/xxx、fix/xxx 等命名）。
  3. 完成功能开发后推送分支，并发起 PR。
  4. PR 描述请说明动机、实现方式、影响范围和验证结果。

仓库根目录的 AGENTS.md（开发准则）与 MAP.md（项目地图）是贡献前必读文件；本页内容即取自二者与源码。直接推送 main 仅限维护者（提交需 GPG 签名，见第 5 节），外部贡献一律走 PR。

2. 环境要求

  • Node.js（建议 20+，自带 Corepack）。
  • 包管理器统一使用 pnpm（版本由 package.json 的 packageManager 字段锁定，通过 Corepack 管理）；请勿使用 npm 或 yarn。 
corepack enable
corepack prepare --activate
pnpm install
pnpm run dev        # http://localhost:23333

3. 项目结构地图

src/           后端源码（TypeScript，tsc 编译到 dist/ 运行）
  server.ts      唯一入口：Fastify 路由 + Socket.IO 事件总装
  game-engine.ts 对局核心（Tick 循环、战斗、连通、投降、回放记录）
  game-engine/   引擎子模块（常量/选点/榜单/编码/迷雾/回放工具/增兵）
  map/           五种 map_mode 地图生成器（纯函数）+ 华夏地区配置
  server/        服务层：auth / captcha / lobby / presence / webhook /
                 server-bot-manager / auto-ban-policy
  types.ts       全项目共享类型与协议定义（改协议基本都要动这里）
  *-store.ts     持久化存储（用户/动态/公告/回放）+ binary-store 底座
static/        纯静态前端（原生 JS + jQuery，无构建，原样下发）
  index.html     首页/大厅（脚本基本内联）
  game.html      对局/回放共用骨架 + main.js + main/（加载顺序敏感）
  styles/        按页面切分的样式表（docs.css 为文档页共享样式），
                 main.css 只做 @import 聚合
  vendor/katex/  本地化 KaTeX（公告/动态与文档页的公式渲染）
  docs.js        文档页共享脚本（登录态/导航/公式渲染）
  develop*.html  本页与 bot 协议权威文档
bot-template/  四个参考 bot（random-patch / simple-strategy / anti-human / apex）
scripts/       维护与测试脚本（数据迁移、bot 冒烟、对局观测分析）
data/          运行时数据（gitignored，见下）
dist/          tsc 构建产物（请勿手动编辑）

数据文件（data/）

users.bin / feeds.bin 用户/动态存储：v8 serialize + brotli 压缩（binary-store 底座），写入前自动生成 .bak 备份，损坏自动回退。
announcement.json 公告：单文件 JSON，原子串行写 + .bak 备份。
server-bots.json 托管策略 bot 的重启恢复状态：{ username, room, template, allowTeam, allowFog } 列表。
replays/ 回放：<id>.rpl（ops-v1 操作流，v8+brotli）、index.bin（索引）、 <id>.rpb.gz（RPB4 观看二进制 gzip 缓存，解码在前端）。

更细的逐文件说明见仓库 MAP.md；它同时规定了「改什么动哪里」的速查表（改协议需同步 src/types.ts、static/develop-bot.html、bot-template/ 与前端消费方）。

4. 常用命令（package.json scripts）

pnpm run dev tsx 直跑 src/server.ts 开发服务器（默认端口 23333，PORT 环境变量或 --port 可覆盖）。
pnpm run build tsc 类型检查并编译 src/ 到 dist/。
pnpm start 运行构建产物 dist/server.js（生产方式）。
pnpm run lint ESLint 检查（仅 src/**/*.ts；lint:fix 自动修复）。
pnpm run format Prettier 自动格式化（src/**/*.ts、static/**、README.md、AGENTS.md）。
pnpm run test:bot bot 集成测试：临时数据目录起服务，两个 random-patch-bot 自动开局对局即通过。
其余 test:* 各模块回归脚本（server-bot 托管、lobby 守卫、迷雾、多线、部署更新、presence、存储、地图生成、回放缓存等，共 25 个），均为自包含冒烟/单元测试，按需单跑；部分需先 pnpm run build。
pnpm run observe:bot 对局观测/病理分析：录帧并生成 bot 行为报告（维护向，非提交前必需）。

5. 提交前检查与提交规范

提交前最小检查：
  • pnpm run lint、pnpm run build、pnpm run format 均通过。
  • 不混入无关改动，提交主题单一；pnpm-lock.yaml 与 package.json 保持一致。
  • 修改了行为（运行方式、接口、配置等）时，已同步更新 README.md。
  • 新增、删除或移动文件，或改变模块职责/协议时，已同步更新 MAP.md。
  • 合并进 main 的任何改动都必须提升 package.json 版本号（SemVer：新功能 minor，其余 patch）。

提交信息

遵循 Conventional Commits：<type>(<scope>): <subject>。常用 type： feat、fix、refactor、perf、docs、 style、test、chore、ci、revert。subject 用英文祈使句、首字母小写、不超过 72 字符；破坏性变更标注 BREAKING CHANGE:。

合并与签名（维护者流程）

直接提交到主仓库需配置作者 oimasterkafuu <hi@oim.moe> 并启用 GPG 签名。PR 统一由 bump-version-and-merge 工作流处理：在 PR 下评论 OK. <major|minor|patch> [merge|squash|rebase]（仅限维护者），自动提升版本号、检测冲突后合并。

6. 部署机制：推 main 即上线

生产部署以 GitHub main 为准：仓库配置了 push webhook（POST /postreceive，HMAC-SHA256 签名校验），服务端收到后自动执行部署流水线： 

git fetch origin main && git reset --hard origin/main
pnpm install --frozen-lockfile
pnpm run build
（systemd 下 exit 由守护进程拉起重启，否则自重启）
  • 更新排队状态机：有对局进行中时不立即重启——进入排队状态（全站广播 deploy_queued、禁止开新局、对局内显示「系统即将更新」横幅），最后一局结束后立即部署；宽限期（默认 120 秒）到期仍未结束的对局按当前排行榜名次强制清算后部署。
  • 只在本地改等于没有生效；服务器工作区未推送的改动会被下一次自动部署直接 reset --hard 覆盖丢失。因此仓库约定：改动验证通过后第一时间推送到 GitHub。
  • 部署期间浏览器端由 Service Worker 兜底：导航请求失败时显示「正在更新」页（static/updating.html），服务恢复后自动跳回。

7. CI 与自动化

CodeQL push/pull_request 到 main 及每周一定时触发（javascript-typescript，build-mode: none）。扫描出的告警需第一时间修复，不留 open 积压。
Dependabot npm 生态每天检查更新（open-pull-requests-limit: 50）。Dependabot PR 必须第一时间逐个处理，合并走第 5 节的工作流（一律 patch 升版）。
bump-version-and-merge 仓库唯一合并工作流（见第 5 节）：PR 评论触发升版本号并自动合并，dev/ 前缀分支合并后自动删除。

8. 开发边界与约定

  • 大厅、房间、回放、认证、验证码等页面与服务端行为都在本仓库；bot-template/ 为只读参考实现，网站开发不要改动。
  • dist/ 是构建产物，任何情况下不手工编辑；行为与源码不符时先重新 pnpm run build。
  • 前端无构建流程，static/ 原样下发；对局页脚本（main.js 与 main/*）全局化且加载顺序敏感，新增脚本注意顺序。
  • Socket.IO 协议或格子编码变更需前后端同步：src/types.ts、 src/game-engine/map-encoding.ts、src/server.ts、前端消费方，并同步更新 static/develop-bot.html 权威文档。
  • 工具链约定：tsconfig.json 刻意关闭 strict（改动会影响整个编译面）；ESLint 只查 src/**/*.ts；Prettier 风格为单引号/分号/尾逗号/110 列。
  • Issue 与 PR 都在 GitHub 主仓库进行；安全问题与疑似 bug 请先开 issue 描述复现步骤。
