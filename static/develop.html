Roka 网站开发

众人拾柴火焰高。在游玩时，如果你有新想法，欢迎参与开发。

仓库与提交流程

主仓库： https://github.com/oimasterkafuu/Roka

  1. 在 GitHub 上 fork 仓库到你自己的账号。
  2. clone 你的 fork，并创建一个只聚焦单一主题的分支。
  3. 完成功能开发后推送分支，并发起 PR。
  4. PR 描述请说明动机、实现方式、影响范围和验证结果。

环境要求

  • Node.js（建议 20+，自带 Corepack）。
  • 包管理器统一使用 pnpm（版本由 package.json 的 packageManager 字段锁定，通过 Corepack 管理）；请勿使用 npm 或 yarn。 
corepack enable
corepack prepare --activate

本地开发与检查

pnpm install        # 首次安装依赖
pnpm run dev        # 启动开发服务器（tsx，默认 http://localhost:23333）
pnpm run build      # 类型检查并构建到 dist/
pnpm run lint       # ESLint 检查
pnpm run format     # Prettier 自动格式化
提交前建议至少确认：
  • pnpm run lint、pnpm run build、pnpm run format 均通过。
  • 不混入无关改动，提交主题单一。
  • pnpm-lock.yaml 与 package.json 保持一致。
  • 修改了行为（运行方式、接口、配置等）时，已同步更新 README.md。

目录结构

src/           后端源码（TypeScript + Fastify + Socket.IO）
  game-engine/ 对局规则引擎
  map/         地图生成
  server/      服务拆分模块
static/        纯静态前端（页面、样式、客户端脚本）
bot-template/  机器人模板（含可运行的测试 bot）
dist/          构建产物（请勿手动编辑）

提交规范

提交信息遵循 Conventional Commits：<type>(<scope>): <subject>，常用 type 有 feat、fix、refactor、perf、docs、 style、test、chore、ci、revert。 详细要求见仓库根目录的 AGENTS.md。

网站开发内容边界

  • 大厅、房间、回放、认证、验证码、匹配逻辑等页面与服务端行为。
  • Socket.IO 协议新增字段时，请同步更新前端消费与文档。
  • 地图生成、渲染和性能优化可在独立 PR 进行。
